# Проверка nextStep() на графе

Дата: 2026-10-27. Текущий API: 0.8.3.

Изначально проверялась внешняя обёртка. По результатам проверки `nextStep()`
реализован внутри `src/playback/player.ts`, обёртка удалена. Проверки
`test/next-step-experiment.test.mjs` теперь используют публичный `createPlayer`.
Метод пока находится в рабочей версии, в опубликованной 0.8.3 его нет.

Использован существующий `graphSteps`: BFS графа A—B, A—C.
Алгоритм и `graphScene` переиспользованы без изменений. Каждый полученный
кадр и его проекция сверяются с полной последовательностью этого же графа.
Это автоматический эксперимент, отдельная браузерная страница не добавлена.

## Что подтвердилось

- Конструктор читает и рисует первый снимок сразу; nextStep не отвечает за запуск.
- На границе nextStep читает один следующий снимок и рисует один раз.
- После advance(400) при длительности 1000 мс nextStep завершает текущий
  переход, не читая ещё один снимок.
- Узлы, рёбра и очередь сохраняют соответствие состоянию BFS.
- Последний снимок закрывает генератор. При finalHoldMs > 0 остаётся
  отдельная пауза; следующий вызов завершает её без чтения генератора.
- Повтор после завершения только перерисовывает кадр, как advance(0).
- Ошибка источника и dispose сохраняют существующую семантику закрытия.

## Почему обёртки недостаточно

Формула `stepDurationMs * (1 - frame.progress)` теряет точность.
Воспроизводимый случай: длительность 650 мс, advance(0.3), nextStep().
Получается progress = 0.9999999999999998 вместо 1. При следующем клике
округление оставляет крошечный остаток времени: плеер читает следующий
снимок и останавливается почти в начале перехода. Регрессионный тест теперь
требует точного progress === 1 на обоих кликах и проходит со встроенным методом.

Добавлять epsilon небезопасно: остаток времени может начать следующий
переход и прочитать лишний снимок. Для публичного nextStep нужно работать
с внутренними elapsed/current, точно устанавливая elapsed = stepDurationMs.
Прототип также хранит результат isTerminal для завершения финальной паузы;
встроенный метод сможет использовать внутреннее состояние напрямую.

## Реализация

Добавлен nextStep в createPlayer с контрактом из аудита: один переход
или завершение текущего, один render, возврат Frame, без лишнего чтения.
Сохранён advance для анимации по времени. При ручном управлении использовать
finalHoldMs: 0, чтобы финальная пауза не требовала отдельного клика.
Проверки графа перенесены на настоящий метод. Добавлены проверки единственного
терминального снимка, дробного времени и ошибок render/isTerminal/return,
а также преждевременного окончания источника. Полный набор: 89 тестов успешно.

Упрощение для пользователя: `button.onclick = () => player.nextStep()`.
Алгоритм, формат снимков и визуализация остаются ответственностью приложения.
