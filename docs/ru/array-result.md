# Отметка результата в /array: выбранный контракт

[English](../array-result.md) · [Текущий /array](array.md) · [Текущий статус](current-api.md) · [Политика совместимости](api-compatibility.md)

**Контракт выбран и реализован локально 2026-11-16; публикации нет.**
Рабочая копия поддерживает done({ result }), resultItemIds и colors.result.
Опубликованная 0.16.0 и кандидат 5e2fd18 этого API не содержат. Запись
контракта ниже сохраняет исторический этап до реализации.

## Вызов в алгоритме

Расширяем существующее завершение, без нового метода или дополнительного шага:

```js
// Локальный неопубликованный API; установите архив рабочей копии.
yield array.done({ result: [min] });
```

`result` — нулевые **позиции занятых элементов на момент завершения**.
Trace сам переводит их в стабильные ID. Форма одна для одного, нескольких
или отсутствующих результатов:

```js
yield array.done({ result: [min] });          // Один результат.
yield array.done({ result: [left, right] });  // Несколько результатов.
yield array.done({ result: [] });             // Нет выбранных элементов, в том числе на пустом входе.
```

Это альтернативные завершения разных trace, а не последовательные вызовы.
На пустом массиве допустим пустой результат; result: [0] недопустим.
Пропуск result или result: undefined означает отсутствие отметки. Предыдущий
highlight автоматически не сохраняется. null недопустим: используйте [].

В том же объекте остаются sortedPrefixLength/sortedSuffixLength. Старые done()
и done({ sortedPrefixLength: array.length }) сохраняют смысл. Выбор результата
не утверждает отсортированность, не переставляет элементы, не сравнивает числа,
не вычисляет минимум и не меняет счётчики. Ответ по-прежнему выбирает алгоритм.

Эти гарантии предоставляет createArrayTrace, в том числе trace, передаваемый
в defineArrayAlgorithm. Собственные реализации ArrayTrace сохраняют прежнюю
структурную совместимость; поддержку новой необязательной возможности в них
добавляет само приложение.

Первый объём — отметка **только в done**. Без result()-метода, управления
отметками посреди trace, селектора held, произвольного цвета отдельного элемента,
нового события, неявного сохранения highlight или асинхронной работы.

## Публичные типы и данные

Планируемые дополнения деклараций:

```ts
// /array: новый type-only экспорт; SortedRegions не меняется.
export interface ArrayDoneOptions extends SortedRegions {
    readonly result?: readonly number[] | undefined;
}

// Новая сигнатура существующего члена ArrayTrace.
done(options?: ArrayDoneOptions): ArrayStep;

// Новый необязательный член существующего ArraySnapshot.
readonly resultItemIds?: readonly string[] | undefined;

// Новый необязательный член существующего /canvas ArrayPalette.
readonly result?: string | undefined;
```

Последние три строки — члены соответствующих интерфейсов, а не самостоятельные
объявления для копирования. ArrayPaletteOverrides вследствие этого принимает
colors: { result: '#047857' }. Нового runtime-экспорта нет.

Событие остаётся прежним замороженным `{ type: 'done' }`. Закрытый union
ArrayEvent не расширяется. ID результата находятся в финальном снимке,
а не в событии или Player. Типы ArrayStep/ArrayFrame сохраняются.

В промежуточных снимках trace нет resultItemIds. Завершение без result, включая
result: undefined, тоже не добавляет поле: старая форма снимка сохраняется.
Явный массив result создаёт собственный замороженный массив resultItemIds
в финальном замороженном снимке; для [] это замороженный пустой массив.
Повторяющиеся позиции допустимы: после проверки всех элементов они сводятся
к уникальным ID в порядке первого появления. Входной массив не сохраняется;
его последующая мутация не влияет на снимок.

Это аннотация, не значение результата и не getter индекса. Ссылки Item,
slots, длина, счётчики и нумерация шагов сохраняют прежние правила. Старые
снимки не меняются. ID принадлежат одной сессии: при Restart строки ID могут
повториться, но новый trace начинает без отметки результата.

Поля снимка и палитры необязательны для совместимости со старыми рукописными
снимками, палитрами из шести ролей и структурными fixtures. Отсутствие/
undefined resultItemIds означает отсутствие выделения. Trace выдаёт ID своих
элементов; в рукописном неизменяемом снимке неизвестный ID просто не совпадает
ни с одним видимым элементом. Полного валидатора таких снимков и нового
клонирования/заморозки прикладных данных не добавляется.

## Валидация, атомарность и ошибки

Сохраняем lifecycle: trace должен быть запущен, ещё не завершён, held пуст.
Вызов до start, после done или с удерживаемым элементом сохраняет прежний
домен обычного Error. Нового класса ошибок нет.

После этих проверок, до изменения собственных данных trace:

1. Читаем и проверяем sortedPrefixLength, затем sortedSuffixLength по прежним
   правилам. Пропуск/undefined сохраняет маркер; неверная длина даёт RangeError.
2. Читаем result. Если он задан, нужен настоящий плотный массив позиций;
   iterable-only, Set, typed array и null дают TypeError. Длину и каждый элемент
   читаем один раз. Некорректная подменённая длина даёт TypeError без coercion.
   Каждый числовой ключ должен быть собственным элементом
   массива: дырка даёт TypeError даже при наличии унаследованного значения.
3. Проверяем позиции по порядку. Нужны примитивные целые числа в диапазоне
   `[0, array.length)`. Строки, boxed numbers, NaN, бесконечности, дробные,
   отрицательные/выходящие за границу значения и 'held' дают RangeError,
   как неверные позиции в существующих операциях массива. Проверяются все
   элементы, в том числе повторы.
4. Получаем ID и создаём собственную неизменяемую аннотацию. Затем вместе
   фиксируем sorted-маркеры, фазу завершения и один шаг done.

Каждое поле опций читается один раз в указанном порядке. Исключения getters/
proxy сохраняют исходное unknown, включая undefined. Ошибка не меняет slots,
held, маркеры, счётчики, фазу и следующий индекс шага самого trace; корректный
done можно повторить. Побочные эффекты прикладных getters не откатываются.
Новой защиты повторного управления ArrayTrace этот проект не вводит;
U1 по-прежнему относится к headless-воспроизведению.

Старый порядок ошибок done сохраняется: lifecycle, held, sorted prefix,
sorted suffix. Неверный sorted-маркер побеждает до чтения result. Нормализации
в ошибки Player/Worker и новых правил владения источником нет.

## Штатное отображение Canvas

Один обычный рендерер читает resultItemIds из frame.current. Новая роль result
по умолчанию зелёная: `#047857` для light, `#34d399` для dark. colors.result —
независимое необязательное переопределение; настройка sorted/active его не
меняет. Копирование палитры, обработка undefined и тождество alias
createSortRenderer сохраняются.

Приоритет цветов: **held > active > result > sorted > обычный столбец**.
Без ID результата прежние приоритеты и цвета не меняются. У обычного done нет
активных элементов, поэтому выбранные результаты зелёные, остальные сохраняют
обычные/sorted-цвета. Пустой массив не подсвечивается; несколько ID выделяют
все соответствующие видимые столбцы. В рукописном кадре с пересечением result
и active/held побеждают эти прежние более приоритетные роли. Неизвестный ID
не окрашивает другой элемент.

Отметка берётся из текущего снимка, как событие и sorted-маркеры, без цветовой
интерполяции и памяти прошлых render-вызовов. Она действует с перехода к
отмеченному current-снимку и сохраняется на его endpoint/hold. Повторный render,
resize, обратный seek и повтор буфера получают цвет из самого кадра. Перемотка
на снимок без resultItemIds убирает отметку; Restart начинает новую сессию без
неё. Неявного переноса на следующие снимки нет.

Раскладка, подписи, контекст Canvas, shape объектов/data arrayScene, matching
сцен, владение DPR/viewport и lifecycle рендерера не меняются. Заголовок Canvas
продолжает показывать done; подменять событие и создавать второй рендерер не
нужно. Метаданные результата — обычные сериализуемые данные снимка, без новых
правил Worker и новых требований к окружению.

## Подключение quickstart

Quickstart для фиксированного непустого массива сохраняет локальный индекс min
и текстовый итог. Его завершение:

```js
result.textContent = 'Minimum: ' + array.at(min).value;
yield array.done({ result: [min] });
```

Отображение снова использует один обычный рендерер:

```js
const renderer = createArrayRenderer({ theme: 'light' });
const player = new Player(container, {
  viewport: canvas,
  stepSource: () => minimum([7, 3, 5, 2, 6]),
  isTerminal: step => step.event.type === 'done',
  render: frame => renderer.render(ctx, frame),
});
```

Нынешние главный и ручной quickstart занимают по **31 строке JS**: фиксированный
непустой вход, один рендерер и штатная отметка результата. Первоначальные 33
строки проекта включали ветку пустого входа; последующее поручение пользователя
её убрало. Поддержка пустого массива в библиотеке сохраняется.
source/asyncSource/history сохраняют свои правила. Player и createArrayPlayer
завершаются на done независимо от наличия результатов. closed, dispose, окно
перемотки и планирование не получают нового контракта.

## Совместимость и приёмка реализации

По U3 проект рассчитан как **аддитивное расширение**: новый type-only экспорт,
необязательные поля опций/снимка/палитры, без нового обязательного члена
ArrayTrace и расширения закрытого ArrayEvent. Старые вызовы, структурные
реализации, стандартные цвета, import boundaries и старые trace должны
остаться совместимыми. Сам SortedRegions не меняется. Обязательные result-поля,
новый event-case или изменение прежнего смысла done/highlight были бы другим,
breaking-проектом. Новые необязательные ключи не гарантируют сохранения
исчерпывающих keyof-карт и недокументированных собственных полей приложений.

Эта классификация относится только к результатам массива. Уже реализованное
расширение union источников Player сохраняет собственную breaking-классификацию.
Документ не сертифицирует кандидата 5e2fd18, не поручает новый кандидат или
публикацию. Результаты runtime/type/package-проверок реализации записаны ниже;
перед отдельно порученной публикацией потребуются актуальные релизные свидетельства.

Приёмка должна проверить:

- Старые done, рукописные snapshots/палитры/реализации ArrayTrace и совместные
  sorted/result-опции; readonly/exact-optional, новый type-only экспорт и
  отрицательные примеры типов во всей выбранной матрице компиляторов.
- Пустой/один/несколько результатов, равные минимумы, отрицательные/нулевые
  значения, повторы позиций, ID после перестановок, неизменяемые собственные
  массивы, прежние счётчики и индексы.
- Неверные массивы/позиции, дырки и inherited-ключи, getter-исключения включая
  falsy, порядок совместных ошибок, атомарный отказ и успешный повтор.
- Обе темы, независимый colors.result, пересечение с sorted/active/held,
  отсутствующие/неизвестные ID, прежние шесть ролей и тождество alias.
- Stateless render/seek/rewind/hold, новый Restart и обычную очистку; отсутствие
  нового терминального события и зависимости headless /array от DOM /canvas.
- EN/RU минимум с одним renderer, одним done({ result }), прямыми кадрами,
  зелёным ответом и без собственного финального снимка/преобразования события.

Изолированная strict TypeScript-проба прилагается к записи проекта ниже.
Она не меняет реальные декларации и не заменяет реализацию/полную матрицу.
Прежние 542 runtime-теста относятся к этапу реализации, а не к проверке API результатов;
свежие результаты приведены в отчёте реализации.
