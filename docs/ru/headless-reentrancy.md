# Повторное управление headless-плеерами: выбранный контракт U1

[English](../headless-reentrancy.md) · [Воспроизведение](playback.md)

**Выпущено с 1.0.0; без изменений в 1.3.1.**
[Текущий API](current-api.md) определяет релизный статус. Правила ниже действуют
для опубликованного пакета; датированные отчёты сохраняют исходный объём проверок.

## Объём и решение

Правило одинаково для `createPlayer`, `createStatePlayer` и `createArrayPlayer`.
Защищаемые команды: `nextStep()`, любой `advance(deltaMs)`, включая ноль, и
`dispose()`.

Экземпляр отклоняет команду, если на том же экземпляре уже активна синхронная
операция или от его имени выполняется прикладной код. Отказ — синхронный обычный
`Error` до нового вызова итератора, render, predicate, изменения времени/кадра
или начала disposal. Очередь, объединение запросов, неявное откладывание и новый
публичный класс/код ошибки не добавляются. Точный текст ошибки не стабилизируется.

Чтение `frame` и `finished` разрешено. Команды другого свободного экземпляра
разрешены. После начала логического disposal повторный `dispose()` безвреден,
в том числе во время собственной очистки источника. Это исключение не разрешает
первый dispose из render, predicate или чтения источника.

Контракты `/player`, `createRewindBuffer` и `createAsyncSource` сохраняются.
В частности, async-адаптер продолжает объединять ожидающие и повторные чтения.
Timeline, emitter и scene dispatch в U1 не входят.

## Какие вызовы приложения охватывает защита

isTerminal — синхронная проверка; она может выполняться несколько раз для одного
шага. U1 не обещает единственный вызов predicate/getter на шаг сверх прежних
контрактов чтения источника и render.

Защищённый интервал включает создание/инициализацию и весь синхронный вызов
команды: получение/чтение источника, terminal checks, render и очистку. Он
заканчивается только при возврате или исключении из внешней операции, после
всей синхронной очистки. Отвергнутый внутренний вызов не получает и не снимает
защиту внешнего вызова.

Охватывается прикладной код:

- `render(frame)` и `isTerminal(step)`;
- фабрика итератора источника и `next()`/`return()`, включая тело генератора и
  `finally`, выполненные этими вызовами;
- getters/функции, которые плеер читает или вызывает при работе с источником:
  getters callback-опций, методы итератора, `done`/`value` результата, поля шага;
- обычные синхронные функции из этих callbacks, в том числе синхронная доставка
  событий и вызов listeners до завершения внешней операции.

Чтение `frame` само может вычислять прикладные getters полей шага. Такой getter
тоже не может вызвать команду того же плеера, даже если внешняя точка входа —
только чтение frame. Вложенное read-only чтение разрешено и не снимает защиту.
Это закрывает обход через accessor, но не обещает завершение рекурсивных
прикладных getters.

Создание по-прежнему синхронно читает/рисует первое значение. Новый handle
недоступен до возврата фабрики; callback с ранней выдачей handle не добавляется.
Захваченная переменная со старым плеером указывает на старый экземпляр, а не на
создаваемый новый.

При ошибке инициализации фабрика не возвращает handle. Очистка предпринимается
только для уже полученного/принадлежащего итератора; доступный кадр при неудачном
создании не обещается. Прежний приоритет первичной ошибки сохраняется.

Плеер владеет итератором. Независимые вызовы методов этого итератора нарушают
контракт владения: защита команд не перехватывает произвольные прямые обращения
приложения к его объектам.

## Матрица команд

| Контекст вызова на том же экземпляре | `nextStep()` / `advance(...)` | `dispose()` | `frame` / `finished` |
| --- | --- | --- | --- |
| Нет активной операции, плеер не disposed | Прежние правила ручного/временного воспроизведения | Сначала логический disposal, затем очистка | Разрешено |
| Активны render, predicate, чтение/получение источника или другая команда | Синхронный Error | Синхронный Error | Разрешено |
| `return()` при штатном terminal-завершении, плеер ещё не disposed | Синхронный Error | Синхронный Error | Разрешено |
| Очистка после явного disposal или после ошибки, уже зафиксировавшей disposal | Синхронный Error | No-op | Разрешено |
| Плеер уже disposed и свободен | Прежний disposed Error | No-op | Разрешено |
| Getter шага, вычисляемый чтением frame | Синхронный Error | Error, кроме уже начатого логического disposal | Разрешено |

Для nextStep/advance отказ занятого экземпляра предшествует валидации аргумента
и проверке disposed. Поэтому `advance(0)`, `advance(NaN)` и команды уже finished
плеера тоже отвергаются внутри callback. Вне этого интервала сохраняется прежняя
валидация: неверная дельта и положительный advance в ручном режиме не потребляют
источник и сами по себе не закрывают рабочий плеер. Для dispose первым действует
правило идемпотентности уже начатого логического disposal.

Закрытие источника на terminal-границе отличается от логического disposal
плеера: он ещё может перерисовать кадр или завершить final hold. Поэтому первый
dispose из такого return отвергается, а не молча считается уже выполненным.

## Наблюдение без изменения

Чтение не запрашивает новое значение, не продвигает время, не вызывает новый
render или isTerminal. Сохраняется frozen wrapper кадра со ссылками на снимки;
тождество wrapper и deep cloning не обещаются.

Во время callback наблюдается состояние, доступное в данной точке внешней
операции. Чтение источника, проверка кандидата, закрытие источника и render —
разные этапы: frame/finished не образуют транзакцию или барьер очистки.
Проверяемый кандидат берётся из аргумента isTerminal(step), выбранный для
рисования кадр — из render(frame). Поздний этап может изменить наблюдения.
Новое обещание отката к последнему успешно нарисованному кадру не вводится.

finished означает завершение воспроизведения, а не disposal. Сохраняемые снимки
принадлежат приложению и должны оставаться immutable. Чтение доступно после
ошибки/disposal с обычным распространением ошибок прикладных getters полей.

## Пойманные и непойманные ошибки

| Ситуация | Результат внешней операции |
| --- | --- |
| Callback поймал отказ внутренней команды и вернул допустимый результат | Внешняя операция продолжается с обычными чтением/render/временем. Отвергнутая команда сама состояния не меняет. |
| Отказ вышел из render, predicate, получения/чтения источника или доступа к шагу во время команды | Прежний operational-error путь: логический disposal, попытка принадлежащей очистки не более одного раза, читаемый кадр и повторная передача того же первичного значения. Новых чтений/render нет. |
| Во время обработки прежней ошибки очистка тоже бросила исключение | Сохраняется первичная ошибка, включая undefined. Повторного return нет. |
| Самостоятельная очистка явного dispose выбросила исключение, включая непойманный отказ команды | Disposal остаётся терминальным; ошибка очистки передаётся один раз. Следующий dispose безвреден. |
| Return при штатном завершении не поймал отказ команды | Самостоятельная ошибка очистки; внешняя операция завершается ошибкой/disposal. Источник не получает второй return. |
| Прикладной getter выбросил исключение из самостоятельного чтения frame | Ошибка чтения передаётся наружу, защита чтения снимается; само чтение автоматически не закрывает плеер. Если ошибка вышла через callback активной команды, её обрабатывает внешняя команда по обычным правилам. |

Откат прикладных побочных эффектов не обещается. Пойманный внутренний Error не
оставляет скрытого fatal-флага. Непойманная ошибка не подавляется только потому,
что началась с отказа повторной команды. Если callback заменил её другим
выброшенным значением, обычные правила первичной ошибки применяются к нему.

При явном dispose логический disposal фиксируется до чтения/вызова return.
Повторный dispose внутри очистки — no-op, next/advance отвергаются. То же правило
идемпотентности действует при очистке после ошибки. Методы итератора не
перекрываются; прежние различия early-close/natural EOF сохраняются. Новая
валидация результата или draining синхронного cleanup не вводится.

Собственный `finally` источника внутри его `next()` ещё относится к активному
вызову источника. Движок фиксирует ошибку только после её выхода из этого вызова;
первый dispose до этого момента остаётся ошибкой повторного управления.
Прикладной finally может заменить своё исключение по обычным правилам языка.

## Другие экземпляры и отложенные команды

Если callback A вызывает свободный B, B работает обычно. Если B синхронно
обращается обратно к A, команды A отвергаются до завершения внешнего вызова A,
а чтение A разрешено. Непойманные ошибки проходят обычный failure-путь каждого
экземпляра; если callback A поймал ошибку B, A может продолжить работу.

Запланированные приложением microtask/timer, выполняющиеся после завершения
внешней операции, — отдельные команды. Они работают при доступном плеере либо
получают обычную ошибку disposed/валидации. Эти поздние ошибки обрабатывает
приложение. Callbacks синхронны: плеер не ждёт возвращённые promises и не собирает
ошибки отложенной прикладной работы. Новый API планирования не добавляется.

## Приёмка реализации

Группы ниже покрыты регрессиями через публичный API в
[test/playback-reentrancy.test.mjs](../../test/playback-reentrancy.test.mjs):

| Сценарий | Требуемое наблюдение |
| --- | --- |
| Каждая команда из render, predicate, next/getter метода/результата и синхронного helper | Внутренний Error до изменений, вызова итератора или лишнего рисования; включить advance(0), неверную дельту и finished-плеер. |
| Пойманный отказ для explicit steps, plain states и array playback | Результат и количество чтений/render совпадают с контрольной обычной операцией, включая частичные переходы и final hold. |
| Непойманный отказ из render/predicate/source | Терминальная ошибка, исходное первичное значение и читаемый кадр, очистка не более одного раза, без перекрытия методов итератора и позднего неявного рисования. |
| Штатный terminal return: пойманные/непойманные next, advance и первый dispose | Правильное продолжение либо ошибка очистки; закрытый источник не смешивается с disposed-плеером. |
| Очистка явного dispose/ошибки: повторный dispose и пойманный/непойманный advance | Идемпотентность, нет повторного return, terminal-state до callback; cleanup не подменяет прежнюю ошибку. |
| Getter при свободном чтении frame, вложенное чтение | Изменение отвергается, само read-error автоматически не закрывает плеер, защита снимается при успехе/исключении; последующая самостоятельная команда работает. |
| A → B, A → B → A с ошибками, пойманными на любом уровне | Защита экземпляра, а не глобальный запрет. |
| Запланированная callback работа после возврата/исключения | Обычные самостоятельные команды; внутренней очереди или await нет. |
| Инициализация и базовое воспроизведение | Прежние время первого render/acquisition, отсутствие раннего handle, source indices, EOF/holds, валидация, приоритет ошибок и владение. |
| Декларации и потребители пакета | Нет нового метода, опции, status-поля, error code/class или экспорта; строгие installed consumers и затронутые пути /player проходят. |

Прежний пример аудита, где возвращается кадр 1, а сохранённый кадр уже равен 2,
описывает незащищённую опубликованную версию. Исправленный движок отклоняет
вложенную команду; это не поставленный в очередь второй шаг.

## Локальная реализация, 2026-11-14

Общий движок защищает команды, инициализацию и чтение полей кадра отдельно для
каждого экземпляра. Логический disposal фиксируется перед очисткой. Приватный
адаптер plain states теперь передаёт return владельцу-движку вместо очистки
внутри завершения генератора до того, как движок успеет зафиксировать disposal.
Ссылка на исходный Iterable сбрасывается при получении итератора, а ссылка
на принадлежащий итератор — при закрытии или EOF.

Публичные регрессии охватывают 61 сценарий для explicit steps, plain states и
массивов: пойманные/непойманные callbacks, getters, штатную/явную/аварийную очистку,
приоритет ошибок, другие экземпляры, отложенную работу и native generator. До
правки первоначальный набор из 59 сценариев падал в 41 случае. Итоговые проверки
всего набора, установленного пакета и деклараций записаны в
[отчёте](../checks/u1-reentrancy-2026-11-14.json). Меняется только приватная
декларация state-steps на IterableIterator; публичные типы и сигнатуры функций
сохраняются. Этот отчёт предшествовал публикации 1.0.0.
