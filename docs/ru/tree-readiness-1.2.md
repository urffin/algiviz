## Объём и выбор версии

База — выпущенная **1.1.0 / 629defe**. Все 43 прежних исходника и десять export-map
записей сохранены. Runtime-зависимости и версии build-инструментов прежние.
Добавляются два независимых entry, поэтому **1.2.0 — совместимый minor-ориентир**;
package.json и оба корневых поля lockfile пока содержат 1.1.0.

| Поверхность | Выпущенная 1.1.0 | Рабочая копия |
| --- | ---: | ---: |
| Entry paths | 10 | 12 |
| Runtime-имён | 24 | 27 |
| Type-only экспортов | 95 | 128 |
| Различных type-only имён | 83 | 116 |

/tree экспортирует createTreeTrace, treeScene и 29 типов; /canvas/tree —
createTreeRenderer и четыре типа. Прежним импортам миграция не нужна. В npm 1.1.0
нет обоих новых entry. С первого выпуска они получают общую защиту 1.x,
без статуса experimental.

TreeKind (ordered/binary), binary slots (left/right), пять вариантов TreeEvent,
два вида TreeObjects и enums рендерера — закрытые наборы; роли — открытые строки.
Третий generic TreeFrame — Kind, четвёртый — Event. Не добавляются root/CJS/private
deep imports, встроенная вставка/AVL, новая опция Player, лес/DAG, SVG или
OffscreenCanvas backend.

## T1: закрыт полными границами нарисованного квадрата

До исправления номинальные границы 6×6 не учитывали половину обводки 1.5px.
У singleton binary с пустым label в (0,0), размером 160×21 и настройками:

```ts
createTreeRenderer({ theme: "light", horizontalGap: 4, emptySlots: "visible" });
```

нарисованный низ был 17.75: отступ 3.25 px вместо 4. Теперь planner расширяет
квадрат на 0.75 CSS px и использует полные painted bounds для viewport, окружностей,
текста, реальных маршрутов и соседних слотов, включая последующие captions.
Прежняя проверка обводки stub и геометрия рисования не менялись.

Небезопасные квадраты на 160×21 пропускаются; на 160×24 оба рисуются с нижним
отступом 4.25 px. Отдельные fixtures проверяют соседний узел, подпись и слот.
Все пять постоянных регрессий падали до исправления и проходят после него.
Проверены bitmap ratios 1/1.25/2, hidden/visible fit parity и raw enter/exit alpha.
API и обещания безопасности не ослаблены.

## Проверки и повторное использование

- Новый npm test: **648/648**. Новый installed-package consumer NodeNext/Bundler
  с TypeScript 6.0.3: **403 runtime-регрессии**. Новая bundle-проверка:
  **34 варианта**, включая независимый/lazy tree Canvas и неизменные прежние/UI
  outputs. Пять новых T1-регрессий включены в installed consumer.
- Новый native-прогон: **32 renderer-проверки** и **17 UI-проверок примера**.
  У renderer сохранены 24 сочетания темы/размера/bitmap и добавлены T1-сценарии
  на ratios 1/1.25/2, включая raster omission/positive controls. У примера повторены
  зелёный результат, rewind/seek, Restart, cleanup, BFcache и прежний Canvas/SVG
  на ширинах 960/390. [Native-доказательства](../checks/tree-t1-native-2026-11-19.json).
- Публичные декларации, EN/RU-код и 12-entry inventory прежние. Проверки четырёх
  компиляторов (5.0.4/5.4.5/5.9.3/6.0.3; NodeNext/Bundler) повторно используются
  только для неизменных деклараций/fixtures. Runtime-приёмка изменённого planner
  новая, а не перенесённая из прежнего результата 398 тестов.
- [Исходная ревизия](../checks/tree-readiness-1.2-2026-11-19.json), отчёт примера
  с 643 тестами и прежний renderer-отчёт с 30 проверками сохраняют исторический
  объём. Их хэши не переписываются для сертификации исправленного planner.
- Package/lock остаются 1.1.0; API не меняется. Прежние 43 опубликованных исходника
  и десять export записей сохранены. Из 53 текущих файлов реализации меняется
  только private tree label planner. Примеры неизменны. Dry-run архива: 111 файлов,
  106 dist, включая 12 tree и восемь tree Canvas; examples/tests в пакет не входят.

История выбывших ID растёт с числом всех зафиксированных ID даже при ограниченной
перемотке. Layout, validation и render синхронны; бюджет кадра Player ограничивает
чтение source, не стоимость одной операции. Подписи/слоты могут пропускаться,
fit на границе пары может меняться, промежуточная геометрия — пересекаться.
Неизменяемость payload, unclipped context и рабочий restore остаются обязанностями
вызывающего. Recovery проверяет host throws и сброс bitmap/context, не forced GPU
context loss. Нового benchmark, обещания FPS/O(1) или registry lookup нет.

повтора неизменных native-fixtures. Старый CI 1.1.0 не сертифицирует эти
незакоммиченные дополнения.
