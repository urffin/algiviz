# Готовность AlgiViz к 1.7.0

[English](../readiness-1.7.md) · [Текущий API](current-api.md) · [Политика совместимости](api-compatibility.md#типы-и-расширяемость)

**Историческая ревизия от 22 ноября 2026 года.** Блокер совместимости устранили,
когда рабочий пакет ещё имел версию 1.6.0. Список шагов ниже описывает тот этап.
[Заметки к 1.7.0](release-1.7.md).

## Исходная проблема совместимости

Первая реализация добавляла пятую ветку в закрытый тип
`PlayerOptions<State, Event>`. Следующий код компилируется с декларациями
опубликованной версии 1.6.0.

```ts
import type { PlayerOptions } from '@grundyjs/algiviz/player';

function readHistory(options: PlayerOptions<number>) {
  if (options.source !== undefined || options.asyncSource !== undefined ||
      options.stepSource !== undefined) return;
  return options.history();
}
```

С первоначальными декларациями после этих проверок `history` мог быть `undefined`
(`TS2722`). Исчерпывающая проверка после четырёх исходных веток тоже
перестаёт компилироваться (`TS2322`). Воспроизведено на TypeScript 6.0.3
в NodeNext и Bundler с декларациями из архива, сверенного с
[отчётом о публикации 1.6.0](../releases/1.6.0.json). По U3 такие
существующие потребители должны оставаться совместимыми в минорном релизе.

## Исправление

Реализация сохраняет четыре ветки `PlayerOptions` и добавляет
`PlayerStepHistoryOptions` с отдельной перегрузкой конструктора.
Прежние опции допускают явное `stepHistory: undefined`. Прежняя
перегрузка объявлена последней, поэтому `ConstructorParameters`
возвращает её тип опций. Постоянные проверки закрепляют прежнее
сужение, исчерпывающую проверку и вывод типов из новой фабрики.

## API, примеры и документация

- Фабрика проверяет весь массив до отрисовки. Кадр сохраняет событие и
  исходный индекс целевого шага. При ошибке Restart остаются прежняя запись,
  позиция, кадр и скорость. В `history` поле `frame.event` остаётся
  `undefined`. [Справочник Player](player.md#полная-история-шагов).
- Сортировка пузырьком передаёт записанный кадр штатному Canvas-рендереру.
  Восемь браузерных проверок покрывают два жёлтых столбца внутри обмена,
  повтор перемотки и Restart. В пирамидальной сортировке прошли 44 проверки
  на ширинах 390 и 960 CSS-пикселей. `extract-swap` хранится в кадре Player,
  `swap` — в снимке массива. Массив и дерево перематываются и перезапускаются
  вместе. После исправления типов оба примера прошли целевые тесты.
  Все 73 скомпилированных файла JavaScript побайтно совпали со сборкой
  предыдущего браузерного прогона.
  [Проверка массива](../../test/step-history-array-browser.html) ·
  [Проверка кучи](../../test/heap-player-browser.html).
- Прошли 808 тестов репозитория и 531 тест установленного рабочего архива.
  Проверены строгие потребители TypeScript 6.0.3 в обоих режимах и изоляция
  бандлов. Проверка типов Player также прошла на TypeScript 5.0.4
  в NodeNext и Bundler.
- Оба README и справочники EN/RU отмечают, что `stepHistory` доступен в
  сборке из репозитория. В первоначальной ревизии сверены оба README и
  changelog рабочего архива, а также 322 ссылки и якоря. Точный архив
  1.7.0 требует отдельной сверки документации.

## Оставшиеся релизные шаги

1. Установить 1.7.0 в манифесте и lockfile. Оформить оба README, changelog,
   заметки и справочники EN/RU. Собрать и установить точный архив и до тега
   сверить его README, changelog, версию, экспорты и ссылки.
2. Отправить проверенный релизный коммит и дождаться всех 11 задач CI на его SHA.
3. После разрешения на выпуск создать тег и GitHub Release. Проверить точную
   версию npm, latest, provenance и README в реестре. Сохранить подтверждение
   в документации о публикации EN/RU.
