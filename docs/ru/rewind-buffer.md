# Ограниченная перемотка назад

[English](../rewind-buffer.md) · [Воспроизведение](playback.md)

Добавлено в 0.14.0 в `/playback`: `createRewindBuffer` и тип
`RewindBuffer<T>`. Синхронный `Iterable<T>` может выдавать обычные состояния,
явные шаги или другие неизменяемые значения. DOM, рендерер и таймер не требуются.

```js
import { createRewindBuffer } from '@grundyjs/algiviz/playback';

function* states() {
    for (let x = 0; ; x += 10) yield Object.freeze({ x });
}
const history = createRewindBuffer(states(), { capacity: 3 });
console.log(history.current);       // { x: 0 }; при создании читается одно значение
history.next();                     // { x: 10 }
history.next();                     // { x: 20 }
history.previous();                 // { x: 10 }; источник не читается
history.next();                     // { x: 20 }; повтор из буфера
history.next();                     // { x: 30 }; источник продолжает работу
console.log(history.startPosition); // 1; x = 0 уже удалён из окна
history.dispose();
```

## Окно и навигация

Обязательный `capacity` — положительное безопасное целое число. Он включает
текущее значение: при capacity 1 можно двигаться только вперёд. Буфер растёт
по мере чтения до указанной ёмкости, полная история не собирается. Навигация
и удаление из окна требуют O(1), расширение буфера — амортизированное O(1),
не считая работы `next()`/`return()` самого источника.
Память — O(capacity × размер значения), с учётом общих структур
и дополнительных ссылок, которые могут сохранять источник и приложение.

| Член API | Значение |
| --- | --- |
| `current` | Текущее значение по исходной ссылке |
| `position` | Текущая позиция последовательности, начиная с нуля |
| `startPosition`, `endPosition` | Включительные границы сохранённого окна |
| `canPrevious` | Есть более старое сохранённое значение |
| `canNext` | Есть более новое сохранённое значение либо конец источника ещё неизвестен |
| `sourceEnded` | Источник уже вернул `done: true` |
| `previous()` | Вернуть предыдущее значение окна; на левой границе вернуть текущее |
| `next()` | Повторить следующее значение буфера, иначе запросить одно у источника; на известном конце вернуть текущее |
| `dispose()` | Закрыть незавершённый источник один раз и удалить историю, сохранив текущее значение |

Возврат назад не откатывает работающий алгоритм, не отменяет его побочные
эффекты и не создаёт состояния заново. При движении вперёд сначала повторяются
сохранённые значения. Окно сдвигается только при получении нового значения
на правой границе; возврат и повтор не удаляют значения. В этом адаптере нет
ветвления, reset, произвольного seek, полной истории и асинхронного источника.

Чтения вперёд нет. После последнего выданного значения `canNext` ещё true;
следующий запрос обнаружит конец, сохранив current/position. После этого
`sourceEnded` остаётся true и при возврате назад, а `canNext` снова становится
true, если есть более новые значения буфера. Значение return генератора
игнорируется. Пустой источник вызывает `RangeError` при создании.

Значения не копируются и не замораживаются; сохраняйте данные состояний и
событий неизменяемыми. У явных `Step` сохраняются исходные `index`, `event`
и `state`; позиция адаптера обозначает порядок, а не заменяет `Step.index`.

## Рисование и владение источником

Вызывайте свой рендерер из обработчиков кнопок. Например, точный шаг сцены:

```js
const steps = createRewindBuffer(myTraversal(), { capacity: 64 });
const step = steps.current; // myTraversal выдаёт Step<Scene<MyObjects>, MyEvent>
renderer.render(context, {
    previous: step.state,
    current: step.state,
    progress: 1,
    stepIndex: step.index,
    event: step.event
});
```

Интерполяцию, время и рисование задаёт приложение. Этот объект не является
итератором или `Player`: его нельзя напрямую передать источником в `/player`
или использовать для отката уже созданного forward-only плеера. Браузерный виджет
теперь подключает буфер опцией `rewindCapacity`; см. [описание плеера](player.md).
Для полной записи есть `createTimeline`.

После проверки ёмкости адаптер получает один итератор и сразу читает первое
значение. Он владеет итератором: не продвигайте его отдельно. Для перезапуска
закройте адаптер и создайте новый со свежим источником. При раннем dispose
вызывается `return()`, если он есть. Естественное исчерпание освобождает итератор
без дополнительного `return()`. Повторный dispose безопасен.

После dispose current/position читаются, окно сужается до `[position, position]`,
оба флага навигации false; next/previous вызывают ошибку. `sourceEnded` означает
только естественное исчерпание, не отмену и не сбой. Ошибка чтения источника или
его результата закрывает адаптер, сохраняет последнее успешно принятое
current/position и запускает очистку, не подменяя исходную ошибку. Самостоятельная
ошибка очистки передаётся один раз после перехода адаптера в закрытое состояние.
Повторный вход в команды из callback источника запрещён; чтение состояния
доступно, а повторный dispose из уже выполняющейся очистки безопасен.

См. [контрактные тесты](../../test/rewind-buffer.test.mjs). Команда
`node --expose-gc scripts/check-rewind-memory.mjs --output rewind-memory.json`
проверяет удержание ссылок при ёмкости 3/64 на 10 000 новых значений в каждом случае.

## Локальная проверка, 2026-11-13

Прошли все 204 теста, включая 11 тестов адаптера и 5 120 коротких последовательностей
навигации, сверенных с эталоном полной истории. Установленный tarball проверен
с TypeScript 6.0.3 в NodeNext и Bundler, включая ES2022 без DOM; bundle isolation
прошёл. [Отчёт удержания](../benchmarks/rewind-buffer-memory.json) показывает
освобождение всех проверенных удалённых снимков, ровно capacity активных значений,
одно сохранённое current после dispose при возврате назад, освобождённый итератор
и ноль активных значений после удаления адаптера. Размеры кучи — диагностика
процесса, не пороги и не доказательство о ссылках произвольного приложения.
Версия не менялась, публикация и CI нового коммита не выполнялись.
