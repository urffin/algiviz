# Прототип размеров Canvas

[English](../canvas-viewport-prototype.md) · [План](../optional-player-proposal.md)

Аудит и локальные проверки: 2026-11-12. Помощник находится
[в примерах](../../examples/canvas-viewport.mjs) и не экспортируется npm-пакетом.
Версия 0.12.0, пять публичных точек входа и контракты Canvas-рендерера не изменены.

## Что требуется примерам

| Интеграция | Прежняя настройка размеров | Вывод |
| --- | --- | --- |
| [BFS](../../examples/graph-demo.mjs) | CSS-ширина, высота раскладки, DPR bitmap и transform | Прежнее `height + 2` предполагало конкретную рамку; размеры содержимого и рамки нужно разделять. |
| [Бинарный поиск](../../examples/binary-search-demo.mjs) | Ширина bounding rectangle, перенос строк, DPR bitmap и transform | Ширина содержимого не включает рамку и не принимает CSS-transform после раскладки за логический размер сцены. |
| [Boids](../../examples/boids-demo.mjs) / [песок](../../examples/sand-demo.mjs) | Похожая настройка с явным ограничением DPR до 2 | Ограничение выбирает приложение исходя из качества и памяти. Эти примеры пока не переведены на помощник. |
| [Рендерер массива](../../src/canvas/index.ts) | Bitmap-координаты и identity transform при рисовании | Помощник CSS-координат не должен незаметно менять раскладку, пороги подписей и контракт координат. |

Прототип подключён к BFS и бинарному поиску. Он собирает общую настройку размеров,
добавляет уведомления о смене DPR и явную очистку ресурсов. Это не обещание роста
FPS и не завершённый перенос всех примеров: обработка жизненного цикла также
требует кода приложения, которого не было у прежних коротких observer-фрагментов.

## Предлагаемый локальный интерфейс

```js
import { createCanvasViewport } from './canvas-viewport.mjs';

let frame = null;
const viewport = createCanvasViewport(canvas, {
  onResize: redraw,
  maxPixelRatio: 2, // Явное ограничение необязательно; по умолчанию его нет.
});

function redraw() {
  if (!frame) return;
  const size = viewport.resize(width => Math.max(180, width * 0.6));
  if (size) draw(viewport.context, frame, size);
}

function render(nextFrame) {
  frame = nextFrame;
  redraw();
}
// При удалении: viewport.dispose().
```

Приложение задаёт независимую CSS-ширину, например `width: 100%`, и минимальный
логический размер своей раскладки. Помощник управляет inline CSS-высотой и
размером bitmap. Конкурирующие `height`, `min-height`, `max-height`, aspect-ratio
и `!important` не входят в контракт прототипа. Обратная зависимость ширины от
bitmap и другие writing modes не поддерживаются. Координаты рисования — CSS-
координаты содержимого; CSS-transform после раскладки не задаёт дополнительную
плотность bitmap.

## Гарантии и владение

- При создании берётся 2D-контекст и окно владельца Canvas. Сам импорт не читает
  глобальный DOM. `onResize` обязателен и не вызывается синхронно при создании
  помощника; первая доставка observer может запланировать уведомление.
- `resize(heightForWidth)` измеряет CSS-ширину содержимого. Для border-box
  вычитает горизонтальные рамки/padding и добавляет вертикальные при установке
  CSS-высоты. Высоту определяет раскладка; callback должен быть чистым.
- Результат содержит CSS `width`/`height`, `bitmapWidth`/`bitmapHeight` и
  эффективный `pixelRatio`. Размеры bitmap округляются до целых, минимум один.
  Transform использует фактические отношения bitmap к логическим размерам по
  обеим осям, учитывая округление. Помощник задаёт базовый transform, не paint styles.
- Неизменившиеся bitmap-атрибуты не присваиваются повторно, сохраняя пиксели.
  Изменение bitmap сбрасывает нативное состояние контекста; обработчик заново
  задаёт свои параметры рисования. Сам помощник не очищает и не рисует кадр.
- Без layout box либо с нулевой шириной resize возвращает null, не вычисляя
  высоту и не меняя bitmap/CSS-высоту. Это покрывает `display: none`;
  `visibility: hidden` сохраняет размеры раскладки.
- Некорректная высота и числовое переполнение bitmap отклоняются до записи.
  Нативные пределы памяти зависят от браузера; откат пикселей при такой ошибке не
  обещается. Ошибки callback уведомления передаются приложению.
- ResizeObserver, resize окна и изменения resolution media объединяются в один
  RAF-вызов. Обратные уведомления только от высоты при прежних ширине/отступах/DPR
  игнорируются. Уведомление не запрашивает состояние алгоритма и не задаёт время плеера.
- Dispose окончателен и идемпотентен: отключает observer, DPR/оконные слушатели и
  отложенный вызов. CSS-высота, bitmap, transform и рисунок остаются. При BFcache
  приложение создаёт новый помощник до перезагрузки плеера; оба примера соблюдают
  этот порядок обработчиков.

В реализации учтена браузерная документация по
[CSS-размерам](https://developer.mozilla.org/en-US/docs/Web/API/Window/getComputedStyle),
[изменению DPR и повторной установке resolution query](https://developer.mozilla.org/en-US/docs/Web/API/Window/devicePixelRatio)
и [отложенной обработке resize без обратной связи observer](https://developer.mozilla.org/en-US/docs/Web/API/ResizeObserver).

## Проверки и ограничения

`npm test`: **182 теста прошли**, включая десять новых
[проверок viewport](../../test/canvas-viewport.test.mjs). Они покрывают дробные
размеры/DPR, обе box models, отсутствие повторной записи атрибутов, чтение
источника, ограничение DPR, скрытые/нулевые размеры, валидацию и очистку ресурсов.
Прежние тесты общего контроллера также проверяют восстановленное браузером
значение режима без изменения кадра или закрытия источника.

Во встроенном браузере оба примера проверены с историей и генератором при
390 × 844 и 1100 × 900. Фактический DPR был **1**:

| Пример | Ширина браузера | Ширина содержимого / bitmap | Высота содержимого / bitmap |
| --- | ---: | ---: | ---: |
| BFS | 390 | 341 | 578 |
| BFS | 1100 | 1030 | 344 |
| Бинарный поиск | 390 | 343 | 384 |
| Бинарный поиск | 1100 | 1032 | 130 |

Resize сохранил Step 1 в обоих режимах и позицию 650 мс для истории. После
возврата на BFS сеанс оставался работоспособным. Проверка выявила восстановление
значения Generator в select поверх нового сеанса истории; общий контроллер
теперь синхронизирует select после pageshow, не перезагружая и не продвигая
источник. После исправления ошибок и предупреждений консоли нет. Временные
настройки viewport сброшены.

Дробный/высокий DPR и его изменение отдельно от размера пока проверены модульно,
а не на физическом HiDPI-дисплее. Инструмент браузера не предоставлял прямое чтение
нативного transform контекста; точные значения проверены тестами viewport.
Эти локальные проверки не расширяют матрицу браузерной поддержки и не заменяют
проверки установленного пакета для будущего экспорта.

## До публичного API

Согласовать имя, точку экспорта и владение CSS-высотой/контекстом. Решить, нужен
ли bitmap-вариант для рендерера массива. Проверить реальные HiDPI/zoom-изменения
и появление/исчезновение области рисования перед расширением гарантий. Затем
добавить типы, установленных потребителей, перечень экспортов и проверку изоляции
сборок для выбранной точки входа. Перенос в пакет и релиз — отдельные шаги.
