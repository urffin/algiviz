# Canvas viewport: зафиксированный контракт API

[English](../canvas-viewport.md) · [Прототип и проверки](canvas-viewport-prototype.md)

Решение зафиксировано 2026-11-12. **Точка входа ещё не реализована и отсутствует
в 0.12.0.** Рабочая реализация остаётся в примерах на `7ba76ba`; этот документ
задаёт границы её последующего переноса в TypeScript и пакет.

## Точка входа и зависимости

Выбрана **`@grundyjs/algiviz/canvas/viewport`** с единственным runtime-экспортом
`createCanvasViewport` и тремя экспортами типов: `CanvasViewport`,
`CanvasViewportOptions`, `CanvasViewportSize`.

Это самостоятельная точка входа без переэкспорта через `/canvas`, `/player` или
корневой barrel. Она не импортирует модель массива, диспетчер сцен, рендерер
массива, воспроизведение, UI плеера или примеры. Прежний `/canvas` сохраняет
bitmap-контракт. Помощник не поставляет кнопки, таблицы стилей, алгоритмы или
зависимости от фреймворков. Импорт не обращается к DOM и ничего не регистрирует.
Создание требует DOM Canvas и его окна: ResizeObserver, RAF/отмена, resolution
matchMedia и доступ к вычисленным стилям/раскладке. Декларации требуют DOM-типов;
существующие headless-точки входа остаются независимыми.

Будущий файл реализации — `src/canvas/viewport.ts`, независимо от
`src/canvas/index.ts`. Явное отображение в пакете:

```json
"./canvas/viewport": {
  "types": "./dist/canvas/viewport.d.ts",
  "import": "./dist/canvas/viewport.js",
  "default": "./dist/canvas/viewport.js"
}
```

Прежний allowlist `dist/canvas` включит эти файлы. Wildcard/приватные пути,
корневой экспорт и новая CommonJS-точка не добавляются. Отображение пока записано
здесь; оно попадёт в package.json вместе с существующими целевыми файлами.

## Публичные сигнатуры

```ts
export interface CanvasViewportOptions {
  readonly onResize: () => void;
  readonly maxPixelRatio?: number | undefined;
}

export interface CanvasViewportSize {
  readonly width: number;
  readonly height: number;
  readonly bitmapWidth: number;
  readonly bitmapHeight: number;
  readonly pixelRatio: number;
}

export interface CanvasViewport {
  readonly context: CanvasRenderingContext2D;
  resize(heightForWidth: (width: number) => number): CanvasViewportSize | null;
  dispose(): void;
}

export declare function createCanvasViewport(
  canvas: HTMLCanvasElement,
  options: CanvasViewportOptions,
): CanvasViewport;
```

Используется фабрика без публичного конструктора и дополнительного алиаса.
Настройки захватываются при создании; последующее изменение переданного объекта
не влияет на помощник. Стабильный `context` — 2D-контекст Canvas. `onResize`
обязателен и выполняется синхронно при доставке; помощник не ожидает async-callback.
`maxPixelRatio` — положительное число, включая Infinity; пропуск или явный
undefined означает Infinity. Значения меньше единицы допускают пониженную
плотность. Для смены ограничения создаётся новый помощник после dispose.

## Координаты и владение

| Владелец | Ответственность |
| --- | --- |
| Приложение | DOM Canvas, CSS-ширина независимо от bitmap, минимум содержимого, размещение, функция высоты раскладки, очистка/отрисовка и жизненный цикл плеера/источника |
| Помощник | Inline CSS-высота, ширина/высота bitmap, базовый transform, наблюдение размеров/DPR и отложенное уведомление |

Приложение создаёт не больше одного активного помощника на Canvas и не записывает параллельно
размеры bitmap и не переопределяет его высоту. CSS использует горизонтальный
writing mode и оставляет высоту свободной: конкурирующие height/min-height/max-height,
aspect-ratio, `!important` и обратная зависимость ширины от bitmap не входят в
контракт. Padding и рамки поддерживаются при content-box и border-box. Приложение
задаёт минимум **содержимого**, не принимая border-box ширину за ту же величину.

Логические размеры — CSS-пиксели содержимого до CSS-transform после раскладки.
Для border-box из вычисленной ширины вычитаются горизонтальные рамки/padding,
а к заданной высоте добавляются вертикальные. Для content-box высота задаётся
напрямую. Помощник не увеличивает плотность из-за CSS-transform и не преобразует
координаты указателя.

Пусть r — положительный конечный devicePixelRatio окна; некорректное значение
заменяется на 1, затем применяется maxPixelRatio. В результате `pixelRatio` равен r:

```text
bitmapWidth  = max(1, round(width  × r))
bitmapHeight = max(1, round(height × r))
transform    = [bitmapWidth / width, 0, 0, bitmapHeight / height, 0, 0]
```

Из-за округления фактический масштаб может отличаться от r и между осями.
Каждый успешный resize задаёт этот transform, даже при прежних размерах.
Формула определяет значения для setTransform; чтение нативной матрицы может
округлять их до точности реализации браузера.
Bitmap-атрибуты присваиваются только при изменении значения. Прежние размеры
сохраняют пиксели и остальные параметры контекста; новые сбрасывают нативное
состояние Canvas. Обработчик заново задаёт paint-параметры и использует парные
save/restore для локальных transform и clipping. Помощник не очищает, не рисует,
не восстанавливает произвольное состояние чужого контекста и не откатывает пиксели.

Это **помощник CSS-координат**. Рендерер массива продолжает читать bitmap-размеры
и рисовать с identity transform; подключение помощника не превращает его в
CSS-рендерер. Первый контракт не добавляет bitmap-режим, адаптер рендерера или
изменения порогов подписей.

## Resize и уведомления

`resize` синхронно измеряет ширину, вызывает чистую heightForWidth с положительной
шириной CSS-содержимого, проверяет результат и применяет размеры. Возвращённые
метрики неизменяемы. Callback не меняет раскладку, bitmap или помощник во время
измерения.

Без измеримого layout box, включая display:none и нулевую ширину содержимого,
resize возвращает null. Он не вызывает heightForWidth и не меняет CSS-высоту,
bitmap или transform. Аргумент-функция всё равно проверяется первым. Элемент с
visibility:hidden сохраняет раскладку и может менять размер обычным образом.
Появление измеримой ширины снова может вызвать уведомление.

`onResize` сообщает о необходимости обновления, а не сам меняет размеры или рисует.
Создание не вызывает его синхронно. Первая доставка observer может отложить
уведомление; приложение учитывает, что текущего кадра ещё нет. ResizeObserver,
resize окна и resolution-изменения объединяются максимум в один ожидающий RAF.
Доставка для каждого события, немедленная или в фоне, не гарантируется.

Уведомление требуется при изменении ширины содержимого, применимых вертикальных
отступов или эффективного DPR. Resolution query обновляется при смене исходного
DPR даже тогда, когда ограничение позволяет не перерисовывать. Обратная связь
только от высоты и измерение, уже обработанное resize, не требуют нового вызова.
Сам resize не вызывает onResize синхронно.

Помощник не владеет временем, итераторами или снимками алгоритма. Для сохранения
позиции callback приложения перерисовывает текущий кадр без next/advance и
перезапуска источника. При изменении данных или правила высоты без смены ширины/DPR
приложение само запрашивает перерисовку.

## Ошибки и dispose

| Ситуация | Результат |
| --- | --- |
| Неверный Canvas/onResize/функция высоты | TypeError |
| Неверное ограничение DPR, неположительная/неконечная высота или числовое переполнение bitmap | RangeError |
| Нет 2D-контекста или требуемого браузерного API | Error либо исходное исключение среды |
| Resize после dispose или dispose во время вычисления высоты | Error; последующих записей размеров нет |
| Функция высоты бросает исключение | Исходная ошибка; этот resize не записывает размеры |
| Ошибка подключения после получения ресурсов | Частичные observer/слушатели освобождаются; исходная ошибка сохраняется |
| Ошибка нативной записи CSS/bitmap/transform | Передаётся приложению; уже применённые изменения не откатываются |
| onResize бросает исключение | Передаётся среде; помощник можно удалить, автоматического повтора того же уведомления нет |

Высота — положительное конечное число. Округлённые размеры bitmap — безопасные
целые не больше 2^32−1; CSS-высота с отступами конечна. Проверка завершается до
записей размеров. Нативные пределы памяти зависят от браузера. Точные строки
сообщений об ошибках не входят в контракт.

Dispose синхронен, окончателен и идемпотентен. Он отменяет отложенный вызов,
отключает observer и оконные/media-слушатели. CSS-высота, bitmap, transform и
последний рисунок сохраняются. После dispose resize бросает ошибку; контекст
остаётся нативным объектом приложения. Этот низкоуровневый помощник не добавляет
автоматический pagehide. Приложение вызывает dispose при unmount/pagehide и
создаёт новый помощник на persisted pageshow **до** восстановления рисующего плеера.

## Условия переноса в пакет

Контракт и точка входа определены; реализация и выпуск — отдельные шаги.
Нативные проверки видимости прошли во встроенном браузере при DPR 1. Настоящий
zoom/DPR Chrome проверен 2026-11-13 от DPR 1 до 2.5, с ограничением и без него,
с восстановлением исходного масштаба. Все 12 сценариев прошли при 1.25,
2.5 с ограничением/без него и восстановленном 1. Физические HiDPI-дисплеи
остаются непроверенными; см. [отчёт](canvas-viewport-prototype.md).

Затем реализовать сигнатуры, добавить потребителей установленного пакета,
импорт без DOM, выбранные TypeScript-конфигурации, точные экспорты/запрет приватных
путей и проверку сборок. Прежние сборки должны сохраниться; новая точка не должна
подтягивать массивы, сцены и плеер. CI проверяется для точного будущего кандидата.
Функциональный выпуск планируется как 0.13.0; документ не создаёт релиз и не
приближает автоматически отдельное решение о 1.0.
