# Операции массива и Canvas

[README](../../ru/README.md) · [English](../array.md)

## Собственные алгоритмы

Новые приложения используют следующие точки входа, не импортирующие готовые алгоритмы:

- `@grundyjs/algiviz/array`: операции над массивами и определение генераторов.
- `@grundyjs/algiviz/playback`: универсальное воспроизведение неизменяемых состояний и событий.
- `@grundyjs/algiviz/scene`: типизированные объекты и пользовательские визуализации.
- `@grundyjs/algiviz/canvas`: готовый рендерер массива.

Циклы, условия и порядок операций определяете вы. Регистрация в библиотеке
или изменение AlgiViz не требуются. Например, разворот массива:

```js
import { defineArrayAlgorithm, createArrayPlayer, createArrayTimeline } from "@grundyjs/algiviz/array";
import { createArrayRenderer } from "@grundyjs/algiviz/canvas";

const reverse = defineArrayAlgorithm(function* (array) {
    yield array.start();
    for (let i = 0; i < Math.floor(array.length / 2); i++) {
        yield array.highlight([i, array.length - 1 - i]);
        yield array.swap(i, array.length - 1 - i);
    }
    yield array.done();
});

const options = { stepDurationMs: 350, finalHoldMs: 1000 };
const ctx = canvas.getContext("2d");
const renderer = createArrayRenderer({ theme: "dark" });
const player = createArrayPlayer(reverse.iterate([1, 2, 3, 4]), {
    ...options,
    render: frame => renderer.render(ctx, frame)
});
// Your animation loop calls player.advance(deltaMs * speed).
// No calls while paused; advance(0) redraws after resizing.
// On teardown: cancel your animation loop and call player.dispose().

// Alternatively, retain history and seek:
const timeline = createArrayTimeline(reverse.steps([1, 2, 3, 4]), options);
renderer.render(ctx, timeline.sample(500));
```

`defineArrayAlgorithm` возвращает `iterate(values)` и `steps(values)`. Каждый итератор
владеет отдельным рабочим состоянием, копирует и проверяет входные данные при первом
`next()`. `steps` собирает итератор в замороженный массив. Выдавайте результат каждой
операции сразу через `yield`, начинайте с `start` и заканчивайте `done`. Операция
обновляет рабочее состояние и возвращает неизменяемый снимок, но ничего не рисует.
Плеер вызывает переданный `render` при создании и каждом `advance` или `nextStep`.
Ошибки отрисовки закрывают итератор и передаются вызывающему коду.

## Операции над массивом

| Операция | Действие |
| --- | --- |
| `at(index)`, `held`, `length` | Прочитать замороженный элемент, удерживаемый элемент или длину массива |
| `start(regions?)` | Выдать начальное состояние; вызывается один раз |
| `compare(left, right)` | Подсветить две позиции и учесть одно сравнение; любая позиция может быть `"held"` |
| `highlight(positions)` | Подсветить элементы на этом шаге без изменения счётчиков |
| `swap(left, right, regions?)` | Обменять занятые позиции и учесть две записи; поддерживаются несоседние позиции |
| `select(from, regions?)` | Удержать элемент, оставив пустую позицию; записи не учитываются |
| `shift(from, to, regions?)` | Переместить элемент в пустую позицию и учесть одну запись |
| `insert(to, regions?)` | Заполнить пустую позицию удерживаемым элементом и учесть одну запись |
| `pass(end, regions?)` | Описать завершённый проход без изменения элементов и счётчиков |
| `done(regions?)` | Завершить работу; удерживаемого элемента быть не должно; не сортирует и не определяет отсортированные области |

`regions` может содержать `sortedPrefixLength` и `sortedSuffixLength`.
Пропущенные или явно заданные как `undefined` маркеры сохраняют предыдущие значения,
в том числе при включённом `exactOptionalPropertyTypes` в TypeScript. Автор алгоритма решает, когда область
отсортирована; AlgiViz проверяет границы, но не доказывает упорядоченность. Индексы
начинаются с нуля. Неверные позиции, занятые места назначения и неправильный порядок
операций вызывают исключение до изменения рабочего состояния. `"held"` разрешён только
в `compare` и `highlight`; обе позиции `swap` и `shift` должны быть целыми индексами.
Читайте снимки, а не изменяйте элементы самостоятельно. `createArrayTrace(values)` предоставляет те же
операции напрямую и сразу проверяет входные данные — для собственной оболочки генератора.

## Гарантии модели массива

Эти гарантии относятся к снимкам `createArrayTrace`, в том числе созданным через
`defineArrayAlgorithm`. Они не означают проверку произвольных объектов, вручную
переданных рендереру или плееру.

### Фиксированная длина и один held

Входные значения должны быть конечными числами; пропуски в разреженном массиве,
`NaN` и бесконечности отклоняются. Вход копируется. Число элементов фиксировано:
`length` и `state.slots.length` всегда равны исходной длине. Операции переставляют
элементы, не добавляя и не удаляя их и не меняя их значений.

`held` содержит `null` либо один элемент. `select` переносит занятый элемент в
`held`, оставляя `null` на его позиции. При наличии удерживаемого элемента ровно
одна позиция `slots` равна `null`; в остальное время все позиции заняты.
`shift` переносит занятый элемент в пустую позицию, перемещая пустую позицию на
место источника. `insert` возвращает удерживаемый элемент в пустую позицию и
сбрасывает `held` в `null`. Повторный `select` при занятом `held`, обмен с пустой
позицией и `done` с удерживаемым элементом вызывают исключение.

`insert` возвращает существующий элемент: не добавляет новое значение и не
увеличивает массив. Пустой вход поддерживается: выдайте `start`, затем `done`
без операций по индексам. `pass(end)` принимает позицию с нуля, а не длину или
количество проходов, поэтому неприменим к пустому массиву.

### Стабильные идентичности и неизменяемые снимки

Каждому исходному элементу назначается уникальный в пределах trace `id`.
Идентичность сохраняется при обмене, выборе, сдвиге и возврате; одинаковые
числовые значения всё равно имеют разные ID. Каждый исходный элемент встречается
ровно один раз среди занятых `slots` и `held`. Глобальная уникальность между
разными trace и перезапусками не гарантируется. При объединении нескольких
trace в одной сцене приложение должно разделить пространства их ID.

Каждая успешная операция возвращает замороженные шаг, событие, состояние и массив
`slots`; элементы и массив ID подсветки тоже заморожены. Последующие операции
не меняют предыдущие снимки. Неизменяемые элементы могут совместно использоваться
несколькими снимками. Снимок описывает состояние сразу после операции; `index`
начинается с нуля и увеличивается на один для каждого выданного шага.

### Счётчики

`comparisons` и `writes` начинаются с нуля и накапливаются в пределах trace:

| Операция | Сравнения | Записи |
| --- | --- | --- |
| `compare` | +1 | 0 |
| `swap` | 0 | +2 |
| `shift`, `insert` | 0 | +1 |
| `start`, `select`, `highlight`, `pass`, `done` | 0 | 0 |

`compare` фиксирует сравнение, но не вычисляет и не возвращает результат
упорядочивания. Алгоритм сам читает значения и принимает решение. Чтение через
`at`, `held` и `length` не выдаёт шаг и не меняет счётчики. Счётчики измеряют
операции trace, а не буквальные присваивания JavaScript: представление выбора
как пустой позиции не считается записью массива. Отклонённые операции сохраняют
элементы рабочего состояния, маркеры, счётчики и номер следующего шага; после
ошибки работу trace можно продолжить.

### Маркеры отсортированных областей

`sortedPrefixLength = k` отмечает первые `k` позиций; `sortedSuffixLength = k` —
последние `k` позиций. Это аннотации автора алгоритма. Библиотека проверяет, что
переданная длина — целое число от `0` до `length`, но не сравнивает значения,
не доказывает сортировку и не определяет, занял ли элемент окончательное место.

Префикс изначально равен `0`. Суффикс может отсутствовать до первого присваивания;
отсутствующее значение следует считать `0`, как это делает Canvas-рендерер.
Пропущенные или явно заданные как `undefined` входные поля сохраняют предыдущие
значения; для сброса передайте `0`. Префикс и суффикс независимы: их можно
уменьшать и перекрывать, а сумма не обязана быть меньше или равна `length`.
За осмысленность этих аннотаций отвечает приложение.

Маркеры не переставляют элементы и не влияют на счётчики. `pass` и `done` не
обновляют их без явно переданного `regions`. В частности, `done()` лишь
завершает trace: разворот массива может успешно закончиться с неотсортированными
значениями и нулевыми маркерами. Алгоритм сортировки должен явно отметить
области, упорядоченность которых он установил.

Сортировки вставками и пузырьком реализованы в [examples/algorithms.mjs](https://github.com/urffin/algiviz/blob/master/examples/algorithms.mjs).
Алгоритмы принадлежат приложению и не требуют изменений библиотеки.

## Отрисовка на Canvas

`createArrayRenderer({ theme: "dark" | "light", colors? })` возвращает
замороженный объект с `render(ctx, frame): void`. `createSortRenderer` — тот же
совместимый псевдоним. Тема обязательна; отсутствующая или неверная тема вызывает
`TypeError` при создании. Пропуск `colors` и `colors: undefined` используют
цвета темы, в том числе при `exactOptionalPropertyTypes`.

Рендерер ожидает неизменяемые состояния `ArrayFrame` одного trace фиксированной
длины со стабильными ID и неизменными значениями элементов. Он не проверяет все
инварианты произвольных снимков, составленных вручную. Хранятся максимум две
проекции состояний, поэтому повторная отрисовка, обратная перемотка и изменение
размера не требуют сброса. Изменять сохранённые снимки нельзя.

### Рисование и координаты

Рендерер рисует полный кадр по `ctx.canvas.width` и `height` в пикселях bitmap,
временно устанавливая единичный transform. Приложение задаёт размеры bitmap,
CSS-размеры и `devicePixelRatio`; существующий DPR-transform не используется
для раскладки. Подписи элементов скрываются при ширине ячейки меньше 24 пикселей
bitmap. Для записи используйте canvas с фиксированными размерами экспорта.

Позиции между слотами интерполируются через smoothstep `p * p * (3 - 2 * p)`,
где `p` — progress кадра. Высота столбца отрицательного значения определяется
его модулем, а подпись сохраняет знак; это не график со знаковой осью. События,
счётчики, статус held и маркеры сортировки берутся из `current` без интерполяции.
Приоритет цветов: held, active, sorted, обычный столбец.

Внутри `save`/`restore` отрисовка задаёт единичный transform, `globalAlpha = 1`,
`globalCompositeOperation = "source-over"`, `filter = "none"`, прозрачный цвет
тени и нулевые размытие/смещения тени. Также задаются используемые стили заливки
и текста. Настройки вызывающей стороны восстанавливаются и при исключении
рисования. Это не гарантия независимости от любого свойства Canvas: передавайте
контекст без ограничивающего clip. Унаследованный clip сохраняется; рендерер
не вызывает `reset()` для его удаления.

При положительных размерах bitmap progress должен быть конечным числом в `[0, 1]`;
иначе `RangeError` возникает до рисования и изменения настроек контекста. При
нулевом размере bitmap вызов ничего не делает даже с неверным progress.
Исключения Canvas передаются вызывающей стороне; восстановление настроек не
откатывает пиксели, уже изменённые ошибочным вызовом Canvas. Точные тексты ошибок
не являются стабильным контрактом.

Отрисовка не запускает цикл анимации, не читает шаги алгоритма, не меняет размер
canvas и не записывает видео. Метода `dispose` нет. Большой массив по-прежнему
требует обработки сцены и рисования на каждом кадре; режим генератора не
гарантирует FPS или постоянный объём выделений памяти.

### Адаптер сцены массива

`arrayScene(snapshot)` создаёт `Scene<ArrayObjects>` с объектами `bar`, в данных
которых находятся `item`, `index` и `held`. Занятые позиции сохраняют исходные ID;
held получает индекс пустой позиции. Оболочки сцены, объекты и data заморожены,
а `item` сохраняется по ссылке. Адаптер не клонирует и не замораживает глубоко
элементы ручных снимков и не проверяет повторяющиеся ID. Соблюдайте инварианты
trace выше и разделяйте пространства ID при объединении нескольких trace.

Для другого способа рисования используйте адаптер с собственным обработчиком
`bar` и `createSceneRenderer` из [`/scene`](scene.md). `/canvas` можно импортировать
без браузера в runtime, но его декларациям нужны DOM-типы из-за ссылки на
`CanvasRenderingContext2D`.

### Пользовательские цвета массива

Рендерер принимает частичное переопределение палитры в `createArrayRenderer`
и совместимом псевдониме `createSortRenderer`:

```ts
import { createArrayRenderer, type ArrayPaletteOverrides } from '@grundyjs/algiviz/canvas';
const colors: ArrayPaletteOverrides = { background: '#ffffff', text: '#182230', active: '#e87900' };
const renderer = createArrayRenderer({ theme: 'light', colors });
renderer.render(ctx, currentFrame);
```

`ArrayPalette` задаёт шесть строковых ролей: `background` (весь canvas), `text`
(все подписи), `bar` (обычные столбцы), `sorted` (отсортированный префикс/суффикс),
`active` (подсвеченные, сравниваемые или перемещаемые элементы) и `held` (удерживаемый
элемент; приоритет выше active и sorted). `ArrayPaletteOverrides` — частичная форма
палитры, `ArrayRendererOptions` описывает объект настроек. Значения — строки цветов
Canvas, передаваемые без CSS-проверки. Для пропущенных ролей и `undefined` используется
выбранная тема. Вызовы только с темой и стандартные цвета не изменились.

Переопределения копируются при создании рендерера. Последующее изменение входного
объекта не влияет на результат. Для смены темы или палитры создайте новый рендерер
и нарисуйте тот же текущий кадр. Меняются только цвета, но не воспроизведение,
снимки, раскладка или обработка bitmap/DPR. Попробуйте темы, шесть полей выбора цвета
и сброс в [лаборатории сортировок](https://github.com/urffin/algiviz/blob/master/examples/index.html).
