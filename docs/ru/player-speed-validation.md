# Валидация скорости Player: выбранный контракт U2

[English](../player-speed-validation.md) · [Player](player.md) · [Ревизия API](../api-readiness-0.16.0.md)

**Выпущено с 1.0.0; без изменений в 1.3.1.**
[Текущий API](current-api.md) определяет релизный статус. Правила ниже действуют
для опубликованного пакета; датированные отчёты сохраняют исходный объём проверок.

## Объём и решение

Единый контракт `Player.setSpeed(value: number): PlayerStatus` действует для:

- `source`, включая поток без истории, ограниченную перемотку и лимит за кадр;
- записей `history`;
- `asyncSource`, включая подготовку, ожидание и барьер очистки;
- Worker-источников, подключённых через `asyncSource`.

Это настройка управления виджетом. Она не настраивает генератор, async-адаптер
или Worker и не меняет headless `advance`. Новый метод, опция, поле статуса,
экспорт, код или класс ошибки не добавляются. Начальная скорость остаётся `1`;
опции скорости в конструкторе нет.

Принимается только примитивный JavaScript number: конечный и строго больше
нуля. Любое другое значение синхронно отклоняется встроенным `RangeError` из
realm метода. Это относится и к неверным runtime-типам из JavaScript или
при обходе TypeScript: отдельного `TypeError` для них нет.

Выбор `RangeError` сохраняет поведение sync/history и устраняет зависимость от
источника. Локальная валидация async/Worker теперь тоже выдаёт `RangeError`.
Класс и момент отказа входят в контракт; текст, stack, тождество
ошибок разных вызовов и специальный code — нет. Это решение не стабилизирует
все числовые ошибки других методов и не нормализует исключения приложения,
источника или DOM.

| Вход | Результат |
| --- | --- |
| `1`, положительные дроби, нестандартные значения вроде `1.5` | Принимаются без изменения |
| `Number.MIN_VALUE`, `Number.MAX_VALUE` | Принимаются без изменения |
| `0`, `-0`, отрицательные числа, `NaN`, обе бесконечности | Синхронный `RangeError` |
| `undefined`, `null`, строки, boolean, boxed number, массивы, объекты, bigint, symbol | Синхронный `RangeError` без приведения |

Область эквивалентна `typeof value === "number" && Number.isFinite(value) &&
value > 0`. Не парсить строки, не распаковывать объекты, не вызывать hooks
преобразования, не округлять, не ограничивать и не выбирать ближайший UI-пресет.
Тип параметра TypeScript остаётся `number`. Требования integer/safe integer,
ограничения пресетами и более низкого верхнего предела нет. Нативный список
скоростей сохраняет пресеты и представление нестандартного значения; область
API шире этого списка.

## Порядок проверки и последствия отказа

Именно для этого метода значение проверяется первым: до disposed, защиты
активной операции и доступности во время подготовки/очистки. Это сохраняет
нынешний порядок обоих контроллеров и отличается от порядка headless U1.
Для допустимого значения действуют прежние проверки виджета: сначала disposed,
затем активная операция и повторный вход из render/status.

| Контекст | Неверное значение | Допустимое значение |
| --- | --- | --- |
| Живой idle до Start | `RangeError`, без получения источника | Сохранить скорость, остаться idle |
| Живой paused или playing | `RangeError`, без изменений | Сохранить скорость и намерение воспроизведения |
| Async preparing/waiting или незавершённая очистка | `RangeError`, без изменений | Сохранить скорость, не обходя барьер |
| Живой finished или операционная error | `RangeError`, без изменений | Сохранить скорость, без restart и восстановления |
| Активная защищённая операция источника, render или status callback того же виджета | `RangeError` | Прежний синхронный Error повторного входа |
| Disposed, включая его уведомление об удалении | `RangeError` | Прежний синхронный disposed Error |

Сам отвергнутый вызов не меняет скорость, поля статуса, кадр, окно, baseline/долг
времени и намерение воспроизведения. Не получает/читает/закрывает источник,
не создаёт Worker и не отправляет сообщения, не назначает/отменяет RAF, не
обновляет DOM, не уведомляет status/error callbacks, не дополняет отчёт закрытия
и не запускает отмену/очистку. Уже ожидающие чтение/очистка могут самостоятельно
завершиться позднее: валидация не останавливает независимую async-работу.

Если окружающий callback поймал отказ и вернулся нормально, внешняя операция
может продолжиться. Если ошибка вышла из callback, внешняя операция применяет
прежние правила callback-failure/очистки. Поэтому отсутствие эффектов от
отвергнутого setSpeed не подавляет непойманную ошибку операции, вызвавшей этот
callback. Синхронное исключение не заменяется очередью или rejected promise.

## Допустимое изменение и учёт времени

Вне защищённых callbacks и disposal допустимая скорость применяется до Start,
в ручном режиме, во время подготовки/очистки, на EOF и после операционной
ошибки. Возвращается обычный синхронный `PlayerStatus` с сохранённой скоростью,
выполняется обычное уведомление статуса/UI. Тождество snapshot не обещается.
Ошибки такого уведомления обрабатываются по прежним правилам callbacks; U2
не превращает их в ошибки валидации и не вводит новую границу отката.

Успешное изменение:

- сохраняет точное число, не читая состояние, не рисуя кадр и не меняя позицию,
  progress, окно перемотки и владение источником;
- сохраняет намерения Play/manual-Next/Replay, текущие запросы и подготовку/очистку;
  не запускает и не приостанавливает воспроизведение, не посылает скорость Worker;
- сбрасывает baseline реального времени, в том числе при том же значении;
  накопленные playback-миллисекунды сохраняются и не умножаются повторно;
- применяется к следующим интервалам после установки baseline. Прежнее
  ограничение реальной дельты 100 мс остаётся до умножения. Время ожидания
  не накапливается и не проигрывается с новой скоростью;
- сохраняет error/hasError и не восстанавливает отказавший сеанс.

Скорость сохраняется при Start, Pause, Next/Previous, seek и Restart, включая
установку async-кандидата. Эти команды не сбрасывают её к `1`. Ручной Next
остаётся одним переходом: скорость не разрешает Play без timing и не меняет
ручную навигацию. Завершённому сеансу нужен обычный restart/replay. В ручном
режиме выбор скорости остаётся скрытым, хотя setSpeed доступен.

Любые конечные положительные граничные значения допустимы, даже если последующая
арифметика времени переполнится или не даст представимого продвижения.
Последующая неконечная дельта/задолженность — прежняя операционная ошибка;
валидация не вычисляет будущие дельты, не закрывает источник и не вводит скрытый
потолок скорости. Гарантия точного real-time pacing или точности float не добавляется.

## Приёмка реализации

Регрессии публичного `/player` в [player-speed.test.mjs](../../test/player-speed.test.mjs)
покрывают source/history/asyncSource/Worker, опции потока отключённые и включённые,
ручные и timed-потоки, а также рабочие команды после пойманных отказов.

| Сценарий | Требуемое наблюдение |
| --- | --- |
| Неверные числа и runtime-типы, включая бросающий hook преобразования | Один встроенный RangeError, без приведения и эффектов отвергнутого вызова |
| Минимальное/максимальное положительные конечные числа, дроби и не-пресеты | Точное значение в статусе/результате и custom UI, без ранней арифметики и получения источника |
| Idle, paused, playing, частичный переход, finished и error | Правильный отказ/приём без неявной навигации, Play/Pause, restart и сброса ошибки |
| Async Start/Restart, заблокированный Play/Next, ready slot и отложенная очистка | Сохраняются запрос/намерение; нет отмены, лишнего pull, обхода барьера и проигрывания времени ожидания |
| Неверный/допустимый вызов из защищённых render/status/source callbacks и после disposal | Значение проверяется первым; пойманный отказ безвреден, непойманный идёт по прежнему пути внешней операции |
| Смена скорости при ожидающем RAF, повтор того же значения, долг ограниченного потока | Сброс baseline, без лишнего/отменённого RAF, прежний долг сохранён, новые интервалы используют новый множитель |
| Ручная навигация, Pause/resume, seek, Restart и установка кандидата | Скорость сохраняется; ручное управление и capability-правила прежние |
| Огромное допустимое значение и последующая неконечная арифметика | Сначала успешный приём, затем ошибка только поздней операции по обычным правилам очистки |
| Idle/waiting Worker-поток | Та же host-валидация; без speed-протокола, нового Worker, сообщения и transfer |
| Потребители пакета | Публичные декларации/экспорты и вывод типов источника прежние; runtime-регрессии установленного пакета и NodeNext/Bundler проходят |

## Основания и следующий шаг

Исторический [отчёт проектирования](../checks/u2-speed-contract-2026-11-14.json)
фиксирует read-only пробы до реализации для четырёх конфигураций источника,
runtime-типов, допустимых границ и приоритета callback/disposed. Это baseline,
а не приёмка единого класса ошибок. Worker-пробы здесь остаются idle и проверяют
отсутствие создания Worker; работу транспорта при активном воспроизведении они
не сертифицируют.

Локальная правка заменяет TypeError на RangeError в async-контроллере;
синхронный уже соответствовал контракту. Публичные декларации, экспорты, версия
и зависимости сохраняются. Все 55 новых публичных регрессий прошли; полный
набор содержит 428 успешных тестов. Worker-интеграция использует настоящий
адаптер и endpoint через внутрипроцессный транспорт с клонированием сообщений,
включая отложенные запросы/очистку; это не новая нативная браузерная проверка.
Результаты установленного архива и bundle isolation записаны в
[отчёте реализации](../checks/u2-speed-implementation-2026-11-14.json).

U2 выпущен с 1.0.0. Датированные отчёты выше сохраняют свой исходный объём;
[текущий API](current-api.md) определяет нынешние гарантии и релизный статус.
