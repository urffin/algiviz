# Кандидат 1.3.0

[English](../candidate-1.3.md) · [Changelog](../../CHANGELOG.md) · [Текущий API](current-api.md) · [Готовность Grid](grid-readiness-1.3.md)

**Подготовлен 2026-11-20; не опубликован.** Package.json и оба корневых поля версии
lockfile содержат 1.3.0. Коммит, добавляющий этот документ, определяет кандидата.
Этап включает commit/push и ожидание всех одиннадцати CI jobs на точном SHA.
Тег, GitHub Release и npm-публикация в этот этап не входят.

## Состав и миграция

Относительно выпущенной **1.2.1 / c398d2d** добавлены два независимых ESM-пути:
/grid (createGridTrace, gridScene и 22 типа) и /canvas/grid
(createGridRenderer и пять типов). Общая поверхность: **14 entry, 30 runtime-имён,
155 type-only экспортов (143 различных имени)**.

[Grid API](grid-api.md) предоставляет плотные generic values фиксированной формы,
атомарные replacement/writes вместе с marks/captions, уникальные клетки результата,
упорядоченный путь с повторами и стабильные ID namespace/координаты в сцене.
При неудаче сохраняются state identity, индекс и lifecycle. Payload values
принадлежат приложению; нет неявной числовой интерполяции, wall sentinel и
глубокого клонирования значений.

[Grid Canvas](grid-canvas-api.md) размещает квадратные клетки, явно представляет
значения, измеряет labels/captions и исключает их текстовые области из пути.
Зелёная принадлежность результату приоритетнее role/presenter colors. Путь
использует raw-progress crossfade, стили current-клеток переключаются дискретно.
Canvas/viewport/DPR принадлежат приложению. Проверены context state, приоритет
исходных/falsy host errors и redraw после обычного сброса bitmap.

**Прежним двенадцати импортам миграция не нужна.** Их 53 исходника реализации,
export-map записи, зависимости и версии компиляторов не меняются. Новым grid
импортам нужна **1.3.0 или новее**; действует та же защита совместимости 1.x.
Прежние шаги, кадры, сцены, rewind/seek Player, Restart и dispose не требуют
расширения API. Root/CommonJS import и расширение поддержки браузеров не добавлены.

Отдельный [пример Grid BFS](examples.md#кратчайший-путь-bfs-на-сетке) находит
кратчайший путь в 10 переходов, сохраняет расстояния и показывает недостижимую
цель, нулевой путь, историю и ограниченную перемотку. BFS, препятствия, очередь
и родители принадлежат примеру; это не встроенный алгоритм или файл npm-архива.
Прежний лабиринт с генерацией/BFS/DFS сохранён. Главный quickstart поиска минимума
намеренно закреплён на npm 1.0.0 и остаётся воспроизводимым.

До npm-публикации новые импорты проверяются по локальному архиву с точной версией.
README/changelog/API описывают состав версии 1.3.0, не заявляя существование
тега, результата CI или уже выполненной публикации в registry.

## Проверки и оставшиеся шаги

[Отчёт подготовки](../checks/candidate-1.3.0-2026-11-20.json) фиксирует свежие
тесты репозитория, точный архив версии, strict installed NodeNext/Bundler
consumers, bundle isolation и хэши файлов/деклараций/документации. README.md,
ru/README.md и CHANGELOG.md внутри архива сверяются с исходниками и четырнадцатью
exports до фиксации коммита.

Native-приёмка переиспользуется после сверки renderer/algorithm/control code,
compiled runtime и fixtures: **18 renderer** и **23 example UI** проверки.
В BFS HTML меняется только абзац статуса версии; controls, markup и поведение
в остальном идентичны. Одна проверка текста версии обновлена и входит в свежий
набор тестов. Нового browser-прогона или benchmark нет. См.
[renderer evidence](../checks/grid-canvas-browser-2026-11-20.json) и
[example evidence](../checks/grid-player-example-2026-11-20.json).

R0 (ревизия), R1 (metadata/notes) и R2 (локальный архив) закрываются этим этапом.
R3 требует всех **11 jobs на итоговом коммите**: Node 22/24/26 × Ubuntu/Windows
(6), consumers TypeScript 5.0.4/5.4.5/5.9.3/6.0.3 (4), bundle isolation (1).
Результаты проверяются после commit/push; pre-commit отчёт их не заявляет.
CI прежнего релиза не сертифицирует этого кандидата.

R4 остаётся отдельным: разрешить v1.3.0 и стабильный GitHub Release на проверенном
SHA, дождаться npm с OIDC/provenance, проверить exact version, latest, свежую
установку, source SHA/provenance, registry-served README и упакованную EN/RU-
документацию. Publish workflow не требует предшествующих одиннадцати CI jobs.
Подготовка кандидата не создаёт тег и не публикует версию.
