# Дополнительные подписи вершин: контракт /graph и /canvas/graph

[English](../graph-node-captions.md) · [Текущий Graph API](graph-api.md) · [Сравнение BFS](bfs-graph-comparison.md)

**Выпущено в 1.1.0, 2026-11-17.** /graph и /canvas/graph включают неизменяемые
подписи, атомарный mark и размещение по метрикам Canvas. BFS задаёт расстояния.
[Проверки реализации и браузера](../checks/graph-node-captions-implementation-2026-11-17.json)
дополняют историческую [ревизию контракта](../checks/graph-node-captions-contract-2026-11-17.json).
Npm 1.0.0 не содержит графовые entry; зависимости прежние.

## 1. Объём и изменение API

У вершины может быть одна дополнительная текстовая подпись снаружи круга.
GraphNode.label остаётся основным именем внутри. ID, имя, подпись, роль и результат
независимы. Приложение форматирует расстояния, стоимости и номера компонент;
библиотека не считает расстояния и не разбирает разметку. Очередь, значки старта/
цели, изменение подписей рёбер, rich text, клики, solver и опции Player сюда не входят.

Изменённые типы; неизменные типы/методы опущены:

```ts
export interface GraphNodeCaption {
    readonly id: string;
    readonly text: string;
}
export interface GraphNodeCaptionPatch {
    readonly id: string;
    readonly text: string | null;
}
export interface GraphTraceOptions {
    readonly layout?: readonly GraphPosition[] | undefined;
    readonly nodeCaptions?: readonly GraphNodeCaption[] | undefined;
}
export interface GraphMarkUpdate {
    readonly nodes?: readonly GraphMark[] | undefined;
    readonly edges?: readonly GraphMark[] | undefined;
    readonly nodeCaptions?: readonly GraphNodeCaptionPatch[] | undefined;
}
export interface GraphSnapshot<NodeData = unknown, EdgeData = unknown> {
    readonly graph: GraphInput<NodeData, EdgeData>;
    readonly layout: readonly GraphPosition[];
    readonly nodeMarks: readonly GraphAnnotation[];
    readonly edgeMarks: readonly GraphAnnotation[];
    readonly result: GraphResult | null;
    readonly nodeCaptions?: readonly GraphNodeCaption[] | undefined;
}
export interface GraphNodeView<Data = unknown> {
    readonly node: GraphNode<Data>;
    readonly position: GraphPosition;
    readonly role: string | null;
    readonly result: boolean;
    readonly caption?: string | undefined;
}
export type GraphEvent = Readonly<
    | { type: "start" }
    | { type: "mark"; nodes: readonly GraphMark[]; edges: readonly GraphMark[];
        nodeCaptions?: readonly GraphNodeCaptionPatch[] | undefined }
    | { type: "layout" }
    | { type: "done" }
>;
```

Нового метода GraphTrace, runtime-экспорта или варианта GraphEvent нет. mark
атомарно меняет роли и подписи одним прежним шагом. GraphDoneOptions, GraphEdgeView,
ключи/типы GraphObjects и Step/Frame прежние. GraphNodeCaption и
GraphNodeCaptionPatch — два новых type-only экспорта.

Необязательная опция Canvas:

```ts
export interface GraphRendererOptions {
    readonly theme: "light" | "dark";
    readonly colors?: { readonly [K in keyof GraphPalette]?: string | undefined } | undefined;
    readonly roleColors?: Readonly<Record<string, string>> | undefined;
    readonly nodeCaptions?: "auto" | "hidden" | undefined;
}
```

По умолчанию auto; hidden отключает измерение/рисование подписей, но не проверку
снимка. Опция — own data field: отсутствие/undefined означает auto; любое значение
кроме auto/hidden даёт TypeError после прежних проверок theme/palette/role options. Без непустых подписей базовое рисование/fit/управление прежние. Callback
с замыканием на изменяемую Map расстояний и новые обязательные поля палитры не нужны.

## 2. Снимок, обновления и валидация

- Начальные nodeCaptions в options допустимы в любом порядке. Конструктор сразу
  копирует/замораживает записи и массив, хранит их в порядке вершин. Новый trace
  всегда выдаёт замороженный nodeCaptions, изначально [] при отсутствии опции.
  Поле типа необязательное: старый снимок без поля или с undefined допустим,
  graphScene трактует его как []. Текст копируется, а не читается из node.data.
- mark({ nodeCaptions }) меняет подписи по ID. Пропущенная/undefined коллекция или
  [] сохраняет подписи. Пропущенный ID сохраняет прежний текст. text:null удаляет;
  text:"" хранится, но не рисуется; text:undefined недопустим. Для полного сброса
  нужно явно передать null по каждому ID.
- ID — точная непустая строка существующей вершины. Повторы в одном патче запрещены
  даже при одинаковом тексте. Неизвестный/повторный ID — RangeError. Неверные
  записи/массивы/скаляры, разреженные массивы, accessors и неверный ID/text —
  TypeError. Текст — любая примитивная строка, включая пустую; без приведения типов.
  В initial/snapshot допускается только строка, не null. Снимок уникален и идёт
  в порядке вершин; патч/событие сохраняет входной порядок.
- Действуют прежние own-data/plain-record/dense-array capture и busy/lifecycle
  guard. Конструктор: граф, capture options, layout, initial captions. mark:
  guard; capture полей nodes/edges/nodeCaptions; проверка nodes, edges, captions;
  затем единый commit. В записи подписи: capture id/text, проверка типов,
  принадлежности вершинам, уникальности. Accessors/callbacks не вызываются,
  исходные proxy throws сохраняются; неизвестные поля игнорируются. graphScene
  проверяет подписи после marks и перед result.
- Ошибка сохраняет snapshot, индекс и фазу; неверный текст не может частично
  применить роли. Успех выдаёт ровно один mark, включая no-op. Новые mark events
  содержат скопированный замороженный патч nodeCaptions ([] при пропуске); поле
  в типе остаётся необязательным для старых событий. start содержит initial
  captions в State без нового события. setLayout сохраняет текст; done сохраняет
  подписи, роли и позиции, задаёт result и закрывает trace. Мутации после done
  запрещены; новых гарантий identity/константной стоимости нет.

Снимок хранит полные подписи, не только delta/event. Старые снимки не меняются
после обновлений или правок входных данных. Строки/записи/массивы cloneable;
контракты Async/Worker и формат транспорта не меняются.

## 3. Сцена, перемотка и переходы

graphScene добавляет необязательный caption в graphNode.data из таблицы текущего
снимка; при отсутствии — undefined. ID, namespace, слои, routing и graphEdge
прежние. Отдельных объектов сцены для подписей и DOM-зависимостей нет. Другие
backend сами размещают полученный текст.

Renderer читает view выбранного endpoint, не event или живую переменную алгоритма.
Для существующей/входящей вершины текущий текст действует на всём кадре, включая
progress=0, как текущие роли/result. Текст не интерполируется и не crossfade.
Удалённая текущая подпись не возвращается из previous. У выходящей вершины
допустим прежний caption с её presence до исчезновения, по прежним правилам
endpoint сцены. Позиция подписи следует за интерполированной геометрией вершины.

Seek/Previous/Next восстанавливают подписи из previous/current State и progress,
не отменяют trace-команды и не проигрывают патчи. Одинаковые endpoints/progress,
логический размер и метрики шрифта дают одинаковое размещение независимо от
порядка посещения/кэша. При блокировке кандидата текст/якорь могут переключиться
дискретно; плавное или навсегда закреплённое размещение не обещается. Resize/DPR
меняют представление без чтения источника или нового шага.

Pause сохраняет кадр/текст. Restart возвращает начальное состояние записи или
новый trace потока вместе с начальными подписями; конечные расстояния не протекают
в новый запуск. undefined Frame.event в истории и async/Worker не мешает подписям.
Изменения Player/ядра не нужны.

## 4. Размещение без пересечений

Гарантия относится к **резервируемым областям новых видимых подписей**, а не к
планарности или исправлению прежних пересечений графа/основных имён. Часть подписей
может не показаться: произвольно плотный граф, совпадающие вершины, маленький
Canvas, длинный текст и рёбра не позволяют обещать видимость всех подписей.

Правила auto:

1. Fit вершин/рёбер прежний. Подписи не двигают вершины, не меняют топологию,
   маршруты, размер Canvas и основное имя. Координаты — логические CSS px из
   явного size; DOM/window.devicePixelRatio не читаются.
2. Одна горизонтальная строка, шрифт renderer 12px sans-serif, цвет текста темы
   независимо от роли/result. Непрозрачный фон — прежний background. Для вывода
   группы TAB/CR/LF/U+2028/U+2029 заменяются пробелом; исходный State не меняется.
   Пустые/состоящие только из пробелов строки не рисуются.
3. Резервируется весь измеренный text/ink cell высотой минимум 16px, поля по 4px
   слева/справа и по 2px сверху/снизу. Текст не сжимается, не уменьшается и не
   обрезается. Полный бокс шире 120 CSS px или доступного viewport пропускается;
   исходный текст остаётся в State. Без надёжных границ текста подпись пропускается.
4. В порядке вершин проверяются восемь кандидатов: снизу, сверху, справа, слева,
   справа-снизу, слева-снизу, справа-сверху, слева-сверху. Боковой бокс находится
   снаружи круга с зазором 4px; варианты выше/ниже смещают центр по вертикали на
   радиус вершины. Верхний/нижний бокс отделён от круга на 4px. Бесконечного
   поиска, force layout или запоминания победителя прошлого кадра нет. Числа/
   порядок задают начальный дизайн, а не публичную гарантию точных пикселей.
5. Кандидат должен быть внутри viewport с отступом 4 CSS px и свободен от всех
   кругов/основных текстов вершин с ненулевым presence, штрихов рёбер/петель,
   стрелок, подписей/весов рёбер и уже принятых подписей. Дополнительно — зазор
   2px от их painted/reserved bounds. Для кривых нужны консервативные области
   без непроверенных промежутков: проверки концов/редких точек недостаточно.
   Лишнее консервативное скрытие допустимо, но должно пройти критерий BFS ниже.
6. Выбирается первый свободный кандидат; если его нет, подпись этой вершины на
   кадре не рисуется. Порядок графа разрешает конкуренцию; result/active не дают
   приоритета. Скрытие — обычное представление, не ошибка Player и не удаление
   из State. Для полноты приложение сохраняет HTML/accessible вывод. API отчёта
   размещения или tooltip в первый объём не входят.

Проверка снимков/опций и базовой геометрии по-прежнему предшествует Canvas calls.
Измерение/план подписей — следующая host-фаза после save/выбора шрифта и до первой
записи пикселей; ошибки измеренных метрик не являются ошибками входной валидации.
Принятые подписи рисуются последними, после графа/основного текста, без выносных
линий и закрашивания занятого места. Действуют
прежние save/restore, запрет render-рекурсии, числовая проверка и приоритет исходной
ошибки host. Все предоставленные числовые метрики должны быть конечны, width — неотрицательным;
нарушение или непредставимая вычисленная геометрия дают RangeError до рисования.
Отсутствующие/нечисловые обязательные метрики означают непригодные bounds:
после проверки предоставленных чисел подпись пропускается, без приведения типов;
throw из measureText сохраняется как другие Canvas throws. Отсутствие пригодных
ink bounds может скрыть подпись, но исключения host не проглатываются. При нулевом
размере State проверяется, измерения/рисования подписей нет. Восемь кандидатов не
обещают O(1) на кадр: измерение текста и проверки препятствий зависят от объёма.

Гарантия основана на геометрии/резервируемых областях и метриках backend, не на
побитовом равенстве пикселей между шрифтами/браузерами или доказательстве AA.
Реальные метрики Canvas, кривые, DPR и восстановление контекста проверены в
native-отчёте реализации. Изменение шрифта/viewport может менять видимость.

## 5. Проверка расстояниями BFS

Интеграция добавляет подписи в существующий nonterminal mark внутри emit.
Нумерация BFS, очередь, родители, путь и счётчики прежние. Форматирование берётся
из состояния этого шага, а не из поздней версии Map генератора:

```js
const nodeCaptions = nodes.map(({ id }) => ({
    id,
    text: `d = ${distance.get(id) ?? (phase === "traversal" ? "—" : "∞")}`
}));
trace.mark({ nodes: nodeRoles, edges: edgeRoles, nodeCaptions });
// Later: done preserves captions already committed at traversal-done.
trace.done({ result: { nodeIds: path, edgeIds: pathEdges } });
```

nodeRoles/edgeRoles/pathEdges в этом фрагменте — уже подготовленные патчи и точный
выбор рёбер родителей. Это форма подключения; в примере роли вычисляются прежними inline-патчами.
На traversal-done неизвестные расстояния становятся бесконечностью ещё до
восстановления пути; done сохраняет их, а не очищает/вычисляет заново.

| Вершина | BFS 0 | Шаг 13: открыта E | Шаг 51: traversal-done | Шаг 56: finished |
| --- | --- | --- | --- | --- |
| A | d = 0 | d = 0 | d = 0 | d = 0 |
| B, C | d = — | d = 1 | d = 1 | d = 1 |
| D, E | d = — | d = 2 | d = 2 | d = 2 |
| F | d = — | d = — | d = 2 | d = 2 |
| G | d = — | d = — | d = 3 | d = 3 |
| H | d = — | d = — | d = ∞ | d = ∞ |

Критерий реализации: при логическом размере 960×480 стандартная fixed
раскладка BFS показывает все восемь коротких расстояний без движения графа и
пересечений, включая боковой вариант для нижней G. На узких/плотных/длиннотекстовых
входах допустимо скрытие, но нельзя ослаблять проверки ради видимости. Проверить
все пресеты, H, старт=цель, отсутствие цели, обратный порядок рёбер, петли/параллельные
рёбра. Текст независим от result: путь A→B→D→G зелёный с расстояниями, а невыбранная
H всё равно показывает бесконечность. Назад с traversal-done возвращает прежнее —;
назад за discovery возвращает — у этой вершины. Restart возвращает шаг 0. Граница
окна, final hold, закрытие источника и бюджет чтения не меняются.

## 6. Доказательства и совместимость

Реализация прошла 595 тестов, installed consumers с четырьмя версиями TypeScript
и optional bundle checks. Во встроенном браузере — 31 автоматическая проверка
реального Canvas и 7 проверок страницы BFS. Пиксельный oracle использует
изображение графа без подписей, независимо от алгоритма размещения. Подробности
и границы — в отчёте реализации; следующая часть относится к прежнему этапу
контракта.

Историческая изолированная проверка контракта использовала вручную составленные будущие поля снимков и
декларации с текущим публичным playback. Она проверяет доступность расстояний,
перемотку history/stream и совместимость типов, но не реализует и не проверяет
capture подписей, их проекцию graphScene или размещение Canvas. Для размещения
есть фиксированный геометрический свидетель по прежним прямым рёбрам BFS и
консервативным синтетическим боксам текста; это не автоматический solver и не
native-тест шрифта/рисования. Отчёт разделяет проверенное и будущие критерии.

Необязательные поля/типы с теми же вариантами GraphEvent не добавляют обязательных
структурных членов. Это было additive-расширение Graph API до его первого выпуска в 1.1.0; приёмка и consumer/package-проверки записаны в отчёте реализации. Распознаваемые
имена nodeCaptions/caption нельзя одновременно занимать посторонними metadata:
такие локальные fixtures нужно проверить перед переходом. Необязательность типов
сама по себе не доказывает runtime-совместимость; graph entries и подписи
выпущены вместе в 1.1.0.
Восемь прежних точек входа, ядро и Player не расширяются. На этапе контракта было 24 runtime / 93 type-only имени; после реализации
теперь 24 runtime / 95 type-only имени, 83 различных типа. Исторические
отчёты сохраняют свои хэши. Ревизия не означает одобрение релиза, CI или native.
