# Ограниченный кэш сопоставления: скорость и память

[Контракт сцены](scene.md#кэш-сопоставления-в-renderer) · [English](../scene-cache-performance.md)

Локальная, ещё не выпущенная реализация проверена 2026-11-13. Базовое
профилирование и документация отдельно закоммичены в `32b0ee0`. Версия пакета
и публичные экспорты не менялись. Для сравнения взят точный исходник /scene
из опубликованного 0.13.0, `443892cf050cf313defcf055cf28318741502946`.
Хеши текущего кода и методика записаны в [результатах](../benchmarks/scene-cache-comparison.json).

## Реализация и удержание данных

У каждого `createSceneRenderer` один слот кэша: предыдущая/текущая сцены,
упорядоченные соответствия и таблица ID → позиция. Совпадение обеих ссылок на
неизменяемые сцены позволяет повторно использовать план. При промахе обе сцены,
типы и захваченный реестр полностью проверяются до замены слота. Progress
проверяется при каждом вызове. Нет глобального кэша, таблицы истории, сохранения
событий, контекста или вычисленных кадров. Поиск обработчика при рисовании остаётся.

Каждый вызов создаёт новые замороженные переходы и кадр с актуальными presence,
progress, stepIndex, event и собственным поиском связанных объектов. Повторный
вход из обработчика не меняет внешний кадр. Ошибка передаётся наружу без отката
рисования. Сохранённые вызывающим кодом кадры удерживают свои объекты, как прежде.
Renderer удерживает последнюю успешную пару до замены или освобождения своего
экземпляра; новый метод dispose не нужен.

Самостоятельный `createSceneFrame` сохраняет прямое построение без кэша и
промежуточного плана. Индексация с валидацией общая с renderer. Оба API не
копируют и не замораживают пользовательские сцены рекурсивно. Изменение на месте
не сбрасывает кэш; новые снимки должны получать новые ссылки на сцены.

## Проверки

- Все 190 тестов прошли. Шесть новых проверок покрывают актуальность метаданных,
  старые кадры и ссылки, слои/порядок, enter/exit, перемотку и новые ссылки,
  ошибочные попадания/замены кэша, независимость реестров, повторный вход и ошибки
  обработчиков. Самостоятельная функция по-прежнему проверяет каждый вызов.
- Парный benchmark сверяет переходы, порядок, метаданные и поиск ID с выпущенной
  реализацией на всём выбранном окне настоящих примеров.
- Замеры работают в одном процессе Node 22.17.0: сначала до/после, затем после/до.
  Используются те же сцены и политика семи выборок, прогрева и серий. Обработчики
  считают вызовы и выполняют поиск связанного объекта. Canvas в этом сравнении нет.
- Память: 4 000 пар по 512 объектов со своими массивами данных. После каждой
  тысячи пар — три явных GC с переходами между задачами. WeakRef отслеживают старые
  оболочки сцен и активную пару; аудит владения дополнительно подтверждает один
  слот плана. Куча включает весь процесс с TypeScript, а не только кэш. Это
  проверка удержания, а не скорости аллокаций, пика памяти или универсального порога.
- Полный рендерер в Node и нативном Canvas измерен отдельными прогонами. Это
  не контролируемое парное сравнение до/после в одном браузере. Canvas replay
  сравнивается со своим кадром; эталон выпущенного результата даёт сравнение
  переходов выше. Этапы пересекаются и отражают CPU/отправку команд, а не FPS/GPU.
  Прежние ограничения базового профилирования сохраняются.

Проверки установленного из локального архива пакета и все 12 тестов viewport прошли
через `npm run test:package`. `npm run test:bundle` подтвердил изоляцию UI/viewport,
отложенную загрузку и выполнение headless-импортов.

## Решение и оставшаяся работа

Оставить кэш одной пары в renderer: он убирает повторное сопоставление и сортировку
при интерполяции, удерживает O(n) памяти и сохраняет независимые кадры. При промахе
валидация и построение остаются. Не обещать ускорение, если стороны меняются
каждый вызов, при ручных точных шагах или при пересоздании renderer.

При этих замерах стандартный array renderer создавал dispatcher на каждом кадре.
Следующий отдельный эксперимент реализовал [переиспользование dispatcher](array-dispatch-performance.md)
и проверил скорость, память и пиксели. Приведённые выше результаты относятся
только к исходной работе над /scene; алгоритмы, планировщик, размер кэша проекций,
зависимости и публикация в ней не менялись.
