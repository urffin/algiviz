# Обновлённый кандидат 1.0.0

[English](../candidate-1.0.md) · [Миграция](migration-1.0.md) · [Текущий API](current-api.md)

**Обновлён 2026-11-16; не опубликован.** Кандидат включает явные шаги Player,
результаты массива и упрощённый quickstart поиска минимума вместе с F1/F2 и
U1–U5. Он заменяет прежний **5e2fd18**. Его 11 успешных CI jobs — история,
не свидетельство проверки нового кода.

Текущее поручение разрешает ревизию, коммит, push в origin и ожидание всех 11
CI jobs нового точного SHA. Тег, GitHub Release и npm-публикация не поручены.
Опубликованная база остаётся [0.16.0](../releases/0.16.0.json).

## Состав кандидата

В package.json и обоих root version lockfile остаётся **1.0.0**. Восемь ESM-
путей, 21 runtime-имя экспортов, зависимости и выбранные окружения прежние.
Сейчас 69 type-only экспортов (57 различных имён), включая новый ArrayDoneOptions.
Публичные опции и типы изменились:

- Player<State, Event = undefined> и PlayerOptions поддерживают отдельную ветку
  stepSource/isTerminal, прямые типизированные кадры и терминальные шаги.
  Расширение source-union по U3 является breaking; исчерпывающим проверкам
  нужна миграция, описанная в [RU](migration-1.0.md)/[EN](../migration-1.0.md).
- done({ result }) записывает неизменяемые ID результата в финальный снимок.
  Необязательная роль result штатного рендерера оставляет выбранные столбцы
  зелёными; событие done, sorted-маркеры и trace без результатов сохраняют смысл.
- EN/RU quickstart использует фиксированный непустой массив, 31 строку JS,
  один renderer и готовые Start/Next/Restart. Pre/обычные состояния, ручной
  array player и сцены/интерполяция остаются учебными этапами, не экспортами алгоритмов.
- Некорректная подменённая длина result-коллекции и дырки отклоняются до фиксации
  завершения; исходные getter-исключения и порядок валидации сохраняются.

Полное поведение описывают [changelog](../../CHANGELOG.md),
[контракт шагов](player-step-source.md) и [контракт результата](array-result.md).
Прежний [отчёт кандидата](../checks/candidate-1.0.0-2026-11-16.json) и отчёты
этапов реализации сохраняют исходные хэши своего этапа.

## Проверки и точная ревизия

[Обновлённый отчёт подготовки](../checks/candidate-1.0.0-explicit-steps-2026-11-16.json)
фиксирует локальные проверки, source/build-хэши и сохранённый архив. Исходники,
тесты и публичные декларации проверяются вместе: прежний архив или CI другого
SHA не заменяют проверку этого кандидата.

Коммит с отчётом фиксирует новый source; его SHA узнаётся после commit, без
самоссылочного SHA внутри документа. Последующий CI-отчёт должен назвать именно
его и полный список jobs. Актуальные прогоны видны в
[CI](https://github.com/urffin/algiviz/actions/workflows/ci.yml); итог текущего
поручения даст точный SHA и URL прогона. Успех CI этим pre-commit документом
не утверждается.

## Оставшиеся релизные условия

1. G1: закоммитить обновлённый кандидат и сверить SHA origin.
2. G2: дождаться успеха **всех 11 jobs этого SHA**: Node 22/24/26 Windows/Linux,
   четыре выбранных TypeScript с NodeNext/Bundler и bundle isolation.
   Skipped/cancelled/failed не считаются успехом. G1/G2 выполняются сейчас.
3. G3: до релиза остаётся целевая native-проверка того же кандидата в прежней
   Windows built-in-browser границе. Старые F1/F2 native-отчёты исторические;
   позднейшие service_info timeouts встроенного браузера не являются успехом.
   Это не препятствует порученным push кандидата и проверке CI.
4. Тег, Release и npm-публикация требуют отдельного поручения после релизных
   условий и последующих проверок точной версии/latest, registry consumers и
   provenance. Один push кандидата не запускает npm-publish.yml: workflow
   реагирует только на опубликованный GitHub Release.
