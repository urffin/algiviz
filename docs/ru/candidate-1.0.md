# Подготовка кандидата 1.0.0

[English](../candidate-1.0.md) · [Миграция](migration-1.0.md) · [Ревизия восьми entry](api-readiness-1.0.md)

**Подготовлен локально 2026-11-16; не опубликован.** Поручены версия/lockfile,
release notes, миграция, локальные проверки и локальный коммит. Push, тег,
GitHub Release и npm-публикация в эту подготовку не входят. Свидетельство
опубликованной базы остаётся [0.16.0](../releases/0.16.0.json).

В metadata пакета и обоих root version lockfile — **1.0.0**. Восемь export-путей,
публичные сигнатуры, зависимости и выбранные окружения прежние. Кандидат включает
накопленные F1/F2-исправления, U1/U2 control/error-изменения, U5-регрессии,
общую U3-политику и согласованную U4-документацию.

[Changelog](../../CHANGELOG.md) помечает 1.0.0 кандидатом, а не релизом.
[Migration notes](migration-1.0.md) описывают наблюдаемые U1/U2-отличия от 0.16.0
и Worker data/error-границу. Промежуточный 0.x-релиз не требуется.

## Локальная проверка

Кандидат прошёл **509 тестов репозитория**, свежие installed-package проверки
TypeScript 6.0.3 в строгих NodeNext/Bundler-конфигурациях (ES2022-only, DOM и
отдельно WebWorker) и bundle isolation. Installed-проверки включают 61 U1,
55 U2, 75 U5 случаев и 121 изолированный публичный F2-сценарий через три
родительских теста. Все восемь EN/RU migration-примеров выполнены успешно.
[Отчёт кандидата](../checks/candidate-1.0.0-2026-11-16.json) фиксирует source/build-
хэши и сохранённый npm-архив со сверенными файлами. Его SHA512 обозначает
локальный payload; сборку при публикации также нужно сверить с этим source и
manifest файлов, учитывая записанные окончания строк.

Прежние native-отчёты F1/F2 остаются историей; новых native/CI-результатов кандидата
не заявляется. Полные тесты/installed/bundle выше — новые прогоны 1.0.0, а не
повторное использование прежних результатов с metadata 0.16.0.

## Оставшиеся релизные условия

1. Локальный коммит подготовки с manifest кандидата фиксирует намеченные source
   и документацию. Результат подготовки записывает точный SHA и хэши архива
   после commit, избегая самоссылочного SHA.
2. По следующему поручению отправить кандидат и получить успех всех **11 CI jobs
   его точного SHA**: шесть Node/OS, четыре выбранных TypeScript с обоими
   resolutions и bundle isolation. Локальные проверки не закрывают G2.
3. Записать целевые native-проверки того же кандидата в прежней Windows built-in
   browser границе: playback/scene, Canvas/viewport, Worker data/cleanup и Player
   waiting/Pause/Next/Restart/dispose. Старые native-отчёты не закрывают G3;
   изменения source/артефакта требуют затронутых перепроверок.
4. Публиковать по отдельному поручению после этих условий: сопоставить
   version/tag/SHA через GitHub Release → npm, затем проверить точную версию/latest,
   свежих registry consumers и signature/provenance. Здесь тег и Release
   не создаются, publish workflow не запускается.

[Отчёт подготовки](../checks/candidate-1.0.0-2026-11-16.json) и неизменяемый Git
коммит обозначают кандидат. Dated pre-F2/F2 audit JSON сохранены без изменений.
