# Готовность AlgiViz к 1.6.0

[English](../readiness-1.6.md) · [Текущий API](current-api.md) · [Требования к окружению](../support-matrix.md#current-support-boundary)

**Историческая ревизия от 22 ноября 2026 года.** По итогам ревизии рабочая
сборка была готова к подготовке релиза, а метаданные пакета ещё указывали
версию 1.5.0. Список шагов ниже описывает этот этап. [Заметки к 1.6.0](release-1.6.md).

| Область | Результат |
| --- | --- |
| [Canvas массива](array.md#подписи-элементов) | `itemLabel` — необязательная функция в `createArrayRenderer` и его псевдониме `createSortRenderer`. Пропуск опции или результат `undefined` сохраняет числовую подпись. Пустая строка скрывает только значение. При ширине ячейки меньше 24 пикселей bitmap рендерер пропускает обе подписи и вызов функции. Неверный тип опции или результата вызывает `TypeError`, а исключение функции передаётся как есть с восстановлением настроек Canvas. |
| [Пирамидальная сортировка с Player](examples.md#пирамидальная-сортировка-с-player) | В панели массива сохранены собственные плитки. На 50% первого обмена штатный рендерер рисовал `2a` и `2b` в одной точке на обеих проверенных ширинах. Плитки разводят все три подписи по высоте. У массива и дерева общие снимки, стабильные ID и позиция воспроизведения. При извлечении `2a` исчезает из дерева и остаётся зелёным в массиве. |
| [Документация EN](../current-api.md) / [RU](current-api.md) | В обоих README и справочниках `itemLabel` обозначен как возможность сборки из репозитория для 1.6.0. Каталог описывает плитки, а руководство по двум панелям показывает, как использовать штатный рендерер с общим снимком и сохранённым `ArrayEvent`. Последний отчёт о публикации относится к 1.5.0. |

## Проверки

- Рабочий npm-архив сравнили с сохранённым архивом 1.5.0 из реестра. Его
  SHA-512 совпал с [отчётом о публикации](../releases/1.5.0.json). Все 16
  путей импорта и список файлов архива совпали. При нормализации переводов
  строк в `dist` отличаются только реализация и декларации точки входа
  Canvas. В декларациях добавлено поле `ArrayRendererOptions.itemLabel`.
  Существующие импорты и опции рендерера совместимы.
- Прошли 803 теста репозитория и 526 тестов установленного пакета. Строгий
  потребитель прошёл проверку с TypeScript 6.0.3 в режимах NodeNext и Bundler.
  Проверка изоляции бандлов прошла. Оба README и changelog побайтно совпали
  с файлами рабочего архива.
- Во встроенном браузере прошли 42 проверки Canvas на ширинах 390 и 960
  CSS-пикселей. Проверены `2a` и `2b`, синхронные обмен и извлечение,
  зелёный отсортированный хвост, Previous, Next, Pause и Restart в обоих
  режимах. При перемотке в середину обмена границы трёх подписей
  разнесены по высоте. [Браузерные проверки](../../test/heap-player-browser.html).

## Оставшиеся релизные шаги

1. Установить 1.6.0 в `package.json` и в двух корневых полях версии
   `package-lock.json`. Оформить changelog, заметки к выпуску EN/RU и оба
   README. Обновить справочники API и окружений для точной версии, используя
   формулировки, пригодные для опубликованного пакета.
2. Собрать и установить точный npm-архив 1.6.0. До тега и GitHub Release
   сверить оба README, changelog, версию, импорты и ссылки из архива
   с соответствующей документацией EN/RU в репозитории.
3. Закоммитить проверенные релизные изменения и отправить в origin.
   Дождаться всех 11 задач CI на точном SHA релиза.
4. После разрешения на публикацию создать `v1.6.0` и GitHub Release на
   этом SHA. Проверить npm 1.6.0, `latest`, подпись реестра, provenance
   и README в реестре. Сохранить отчёт и актуализировать статус публикации
   EN/RU в рамках той же релизной задачи.
