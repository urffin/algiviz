# Необязательный браузерный плеер

[README](../../ru/README.md) · [English](../player.md)

**Ещё не выпущен:** `/player` подготовлен в рабочей копии после коммита прототипа
`12f8fb3`. В опубликованной 0.11.2 этой точки входа нет. Версия пакета пока не

`@grundyjs/algiviz/player` экспортирует класс `Player` и типы `PlayerOptions`,
`PlayerStatus`, `PlayerLabels`. `Player<State>` также задаёт тип экземпляра.
Модуль зависит только от
воспроизведения. Существующие точки входа не импортируют интерфейс и его стили.

## Подключение по запросу

Подготовьте HTML-контейнер с Canvas, SVG или собственным элементом визуализации.
Состояния и отрисовку задаёт приложение:

```ts
const { Player } = await import('@grundyjs/algiviz/player');
const ui = new Player(container, {
  viewport: canvas,
  source: function* () {
    for (const x of [40, 200, 360, 560]) yield { x };
  },
  render(frame) { draw(frame.current.x); },
  stepDurationMs: 1000,
});
// При удалении виджета:
ui.dispose();
```

`viewport` необязателен и должен быть непосредственным дочерним элементом
HTML-контейнера. Плеер временно переносит тот же элемент в оболочку, затем
возвращает его при dispose без очистки рисунка и изменения bitmap-размеров
Canvas. Раскладка, размеры, DPR и способ отрисовки принадлежат приложению.

Конструктор создаёт только интерфейс. Фабрика впервые вызывается по «Начать»; первый
кадр показан на паузе. Автозапуска нет. [Пример](../../examples/optional-player.html)
показывает независимые запись Canvas и поток SVG.

## Запись и поток

| Настройка | Хранение и управление |
| --- | --- |
| `source: () => Iterable<State>` | Ленивое чтение, соседние снимки, неизвестная длительность. Next завершает переход либо читает один следующий снимок. Ещё один запрос после последнего yield обнаруживает конец. Перемотки и Previous нет; для ручного режима время необязательно. |
| `history: () => readonly State[]` | Явно заданная конечная непустая запись без пропусков, хранится целиком. Обязателен положительный `stepDurationMs`. Доступны Previous, перемотка по времени и известная длительность. Фабрика вызывается только при начале сеанса. |

Нужна ровно одна фабрика. Плеер не собирает генератор ради перемотки. Фабрика
должна поддерживать повторный вызов для нового сеанса. Тип состояния выводится
из её результата; выданные состояния нельзя изменять.

`finalHoldMs` по умолчанию 0. `seekBar` по умолчанию true; у потока шкала всегда
скрыта. `seekBar: false` скрывает шкалу записи, сохраняя программную перемотку.
Seek ставит воспроизведение на паузу, ограничивает конечное время границами записи
и не пересоздаёт её. NaN/Infinity отклоняются до изменения рабочего сеанса.

## Управление и жизненный цикл

Экземпляр `Player<State>` содержит readonly `status`, `frame` и методы `start`, `play`,
`pause`, `next`, `previous`, `seek(positionMs)`, `restart`, `setSpeed`, `dispose`.
Команды возвращают `PlayerStatus`, dispose — void. До начала frame равен null,
после dispose последний кадр доступен. Его event равен undefined.

Статус включает фазу, режим, started/timed, скорость, error/hasError, индекс и
progress, а также canStart/canPlay/canNext/canRestart/canSeek/canPrevious.
Позиция и длительность записи задаются в миллисекундах; недоступные значения —
null. Previous/seek потока и неверная скорость вызывают исключение без чтения
источника. Допустимы положительные конечные скорости, включая нестандартные.

Restart показывает первый кадр на паузе; UI-кнопка повтора затем запускает Play.
Программный play не перезапускает завершённый сеанс. Play требует stepDurationMs.
Next во время Play ставит на паузу и завершает один переход. Скрытая вкладка
ставит плеер на паузу без автоматического возобновления. RAF ограничивает дельту
реального времени 100 мс до умножения на скорость: длительные задержки
отбрасываются. Одну тяжёлую синхронную операцию генератора прервать нельзя.

`onStatus` вызывается синхронно, включая исходный idle до завершения конструктора `Player`.
Из render/onStatus нельзя синхронно изменять тот же плеер: повторный вход
отклоняется. `onError` получает операционную ошибку после очистки; исключения
пользовательского onError передаются вызывающему коду. Ошибка подготовки нового
источника сохраняет старый сеанс на паузе. Ошибки источника/рисования/статуса
закрывают отказавший сеанс и останавливают RAF, сохраняя читаемый кадр. Ошибка
очистки не заменяет исходную операционную ошибку. Ошибка отдельного dispose
передаётся после очистки DOM, обработчиков и таймеров.

## Панель и оформление

Панель накладывается на нижнюю часть визуализации и скрывается через две секунды
бездействия после начала. Мышь, касание и фокус с клавиатуры показывают её.
Наведение на панель, удерживаемый указатель/перетаскивание, клавиатурный фокус,
фокус выбора скорости, исходный idle и ошибки удерживают её видимой. Скрытые
кнопки доступны с клавиатуры. Reduced motion убирает fade и показывает текущие
конечные состояния без изменения исходного кадра и чтения новых состояний.
`autoHide: false` либо отсутствие viewport оставляет постоянную панель снизу.
Минимальная высота области overlay — 160 CSS px.

`labels` переопределяет известные роли `PlayerLabels`. Значения — непустые
строки; пропущенные и явно undefined сохраняют значения по умолчанию. Настройки
копируются. Английские подписи, SVG-иконки и стандартные элементы не требуют
фреймворков, шрифтов и внешних файлов. Стили с префиксом создаются при монтаже.
CSP приложения должна разрешать их; API nonce/внешней таблицы стилей пока нет.
CSS-переменные: `--player-border`, `--player-stage`, `--player-panel`,
`--player-text`, `--player-accent`, `--player-error`.

Dispose идемпотентен и удаляет только свой сеанс, RAF, таймер скрытия, обработчики
и оболочку. Рисунок и соседние элементы приложения сохраняются. Pagehide удаляет
виджет; повторное подключение при BFcache/навигации выполняет приложение.
Несколько плееров независимы.

## Импорт и проверки

Импорт модуля безопасен без DOM, монтаж требует DOM-контейнер и его окно с
RAF/matchMedia. Для деклараций `/player` нужны DOM-типы. Проверки `/playback`,
`/scene`, `/array` с одним ES2022 сохранены. Root/CommonJS не добавляются.

Архив npm увеличивается на дополнительные файлы. Для подключения по запросу
нужен import(); фактические чанки и preload зависят от сборщика приложения.
Проверки установленного tarball:

```sh
npm test
npm run test:package -- --resolution all
npm run test:bundle
```

Проверка esbuild сравнивает обычные импорты побайтово с теми же четырьмя модулями
без `/player`, проверяет обычный и динамический импорт UI, исходные/минифицированные
ESM-сборки и граф начальных/отложенных чанков. Минифицированные сборки и ленивый
загрузчик запускаются в Node без DOM. Это проверка конкретной конфигурации,
а не обещание одинакового поведения всех сборщиков.

Проверено в рабочей копии 2026-11-12: **172 теста прошли**. Установленный пакет
прошёл TypeScript 5.0.4, 5.4.5, 5.9.3, 6.0.3 с NodeNext/Bundler, включая прежние
потребители без DOM, вывод типов и отклонение конфликтующих настроек. Точные
размеры и проверка неизменности обычной сборки — в [отчёте](../player-bundle-check.md).
Во встроенном браузере через публичный import map проверены отложенная
инициализация, перемотка записи, Play/Next потока, сохранение четырёх SVG-вершин
после dispose и повторное подключение. Визуальная проверка предшествовала переходу
на конструктор; новая форма API проверена тестами экземпляров, жизненного цикла
и установленного пакета. Ошибок и предупреждений консоли при визуальной проверке нет.
Удалённый CI для точного коммита новой реализации ещё не запускался.
