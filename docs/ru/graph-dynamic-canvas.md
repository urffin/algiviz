# Динамическая топология в /canvas/graph

[English](../graph-dynamic-canvas.md) · [Headless-контракт](graph-dynamic-topology.md) · [Canvas API](graph-api.md#декларации-canvasgraph) · [Стягивание ребра](examples.md#стягивание-ребра)

Режим доступен с 1.5.0. Он включается явно при создании
рендерера. Поведение по умолчанию применимо и к снимкам, составленным приложением.

## Публичный API

Динамические переходы включает новое необязательное поле
`GraphRendererOptions.topologyTransitions`. Фабрика и тип результата те же.

```ts
import type { GraphPalette, GraphRenderer } from "@grundyjs/algiviz/canvas/graph";

export interface GraphRendererOptions {
    readonly theme: "light" | "dark";
    readonly colors?: { readonly [K in keyof GraphPalette]?: string | undefined } | undefined;
    readonly roleColors?: Readonly<Record<string, string>> | undefined;
    readonly nodeCaptions?: "auto" | "hidden" | undefined;
    readonly topologyTransitions?: boolean | undefined;
}

export declare function createGraphRenderer(options: GraphRendererOptions): GraphRenderer;
```

| Значение `topologyTransitions` | Режим |
| --- | --- |
| Поле отсутствует, `undefined` или `false` | Поведение рендерера по умолчанию, включая интерполяцию кривой при смене концов. |
| `true` | Динамические переходы по правилам ниже. |

Значение считывается один раз при создании экземпляра. Действуют правила
собственных data properties. Остальные значения, включая `null`, `0`,
строку `"true"` и объект `Boolean`, дают синхронный `TypeError`. Собственный
accessor отклоняется без вызова. Унаследованное поле игнорируется для
допустимых plain records. Дескриптор и значение новой опции проверяются
после действующих опций, поэтому прежняя ошибка выигрывает, если неверны обе.
Исключение Proxy при чтении дескриптора передаётся как есть.

`theme` остаётся обязательной. По умолчанию используются цвета темы,
пустой набор пользовательских ролей и `nodeCaptions: "auto"`.
`GraphPalette`, `GraphRenderSize`, закрытый выбор подписей и
`GraphRenderer.render<N, E, Event>(context, frame, size)` используются в
обоих режимах. Режим задаётся экземпляру и работает с обычными и
динамическими `GraphSnapshot`, включая кадры без события. Приложение
явно включает режим независимо от фабрики trace и типа события.

Имя `topologyTransitions` резервируется в записи опций. Одноимённое поле
интерпретируется по таблице выше. Для стандартного вызова достаточно прежнего
объекта опций.

```ts
import { createGraphRenderer } from "@grundyjs/algiviz/canvas/graph";

const standard = createGraphRenderer({ theme: "dark" });
const dynamic = createGraphRenderer({ theme: "dark", topologyTransitions: true });
```

Опция компилируется с прежними типами функции и опций. `render` принимает
обычные, динамические кадры и кадры с `event: undefined`.

## Кадр и появление объектов

Режим принимает текущий `Frame<GraphSnapshot<N, E>, Event>` и использует
`graphScene` для каждого снимка. Сопоставление опирается на ID и оба снимка.
Одинаковые правила действуют для кадров с `edit` и с `event: undefined`.
В таблице `p` — `Frame.progress` от 0 до 1.

| Объект | Позиция или маршрут | Непрозрачность |
| --- | --- | --- |
| Новая вершина | Позиция из current | `p` |
| Удалённая вершина | Позиция из previous | `1 − p` |
| Сохранённая вершина | Линейное движение между позициями | 1 |
| Новое ребро | Концы и полоса из current | `p` |
| Удалённое ребро | Концы и полоса из previous | `1 − p` |
| Сохранённое ребро с тем же направлением и концами | Один маршрут с плавным изменением полосы | 1 |
| Перенаправленное ребро | Старый и новый маршруты одного ID | `1 − p` и `p` |

Штрихи, стрелки и видимый текст используют непрозрачность своего объекта или
маршрута. Для ребра непрозрачность не умножается на непрозрачность его концов.
Сначала проверяются оба снимка. Объекты и маршруты с нулевой непрозрачностью
участвуют в расчёте общих границ, но не рисуются и не занимают место при
размещении подписей.

## Перенаправление с тем же ID

У направленного ребра сравнивается упорядоченная пара концов. Обращение стрелки
считается изменением маршрута. У ненаправленного ребра сравнивается
неупорядоченная пара. Перестановка `from` и `to` у такой связи сохраняет один
маршрут с единым порядком концов для расчёта полосы. Переход между направленным
и ненаправленным ребром тоже использует
перекрёстное затухание. Значения `false` и отсутствие `directed` эквивалентны.
Переход между обычным ребром и петлёй подчиняется тем же правилам.

В сцене остаётся один объект `graphEdge` с фазой `update`. При отрисовке он
может дать два маршрута. Старый маршрут разрешает концы в previous, новый —
в current. Если вершина присутствует в обоих снимках, оба маршрута используют
её интерполированную позицию. Появляющиеся и уходящие вершины используют
позицию своего снимка. Стрелка, если она есть, следует касательной своего
маршрута у границы целевой вершины.

Например, при замене `e: A → B` на `e: A → C` в середине перехода видны две
полупрозрачные связи. Старая заканчивается на B, новая — на C. При `p = 0`
видна только старая, при `p = 1` — только новая. Это правило описывает
видимость маршрутов в пределах общей раскладки перехода.

Старый маршрут берёт роль, результат и направление из previous, новый —
из current. Приоритет цвета результата сохраняется для каждого маршрута.
У остальных сохранённых объектов роль и результат берутся из current.
У перенаправленного ребра отображается не более одной подписи. При `p < 0.5`
берётся текст старого маршрута, при `p ≥ 0.5` — нового. Для неё используются
позиция и непрозрачность выбранного маршрута. Действуют обычные правила
подписи и веса, включая явное скрытие пустой строкой.

Сначала рисуются рёбра, затем вершины и дополнительные подписи. Для рёбер
сохраняется порядок сцены. Внутри объекта при двух маршрутах первый — старый.
При размещении дополнительных подписей вершин учитываются обе видимые кривые,
обе стрелки и фактически показанный текст ребра.

## Параллельные рёбра и петли

Каждый снимок задаёт свои `routeIndex` и `routeCount`. Обычные и встречные
рёбра с общей неупорядоченной парой концов делят группу. У петель группа
соответствует вершине. Перенаправление может одновременно освободить место
в старой группе и занять место в новой.

Входящие, выходящие и перенаправленные маршруты используют полосу своего снимка.
У сохранённого маршрута с теми же концами и направлением полоса плавно меняется
от старой к новой. Для этого интерполируется геометрическое смещение, у петли —
геометрия полосы петли. Целые `routeIndex` и `routeCount` остаются данными
снимка. Временное перекрытие маршрутов допустимо, например при обмене полосами
двух сохранённых рёбер или при смене направления стрелки.

Общий transform на переход строится по расположению вершин обоих снимков с
резервом для старых и новых полос, петель, стрелок и обводок. Он постоянен
при изменении `p` в пределах пары снимков. Размер Canvas и DPR задаёт
приложение. На тесной области действуют текущие ограничения читаемости графа.

## Перемотка, Restart и Canvas

Отрисовка определяется парой снимков `previous`/`current`, прогрессом,
логическим размером, bitmap, опциями и метриками шрифта. Previous и Seek
рисуют переданный кадр. Restart рисует начальный кадр. При ненулевых размерах
логической области и bitmap каждый кадр очищает bitmap в предоставленном
контексте без clipping перед отрисовкой фона и графа, в том числе для пустого
графа и прозрачного фона. Предыдущие маршруты
и выделение результата исчезают после перехода по истории. Смена размера
повторно вписывает данную пару. Действующие правила валидации, ошибок Canvas,
восстановления контекста и кеша двух снимков применяются к этому режиму.

В контрольном примере `A → B` → `A → C` стандартный режим рисует одну
непрозрачную интерполируемую кривую для этого ID. При включённой опции в
середине кадра видны два привязанных маршрута с непрозрачностью 0.5.

## Регрессионные проверки

[Проверки команд Canvas](../../test/graph-topology-canvas.test.mjs) входят
в тесты репозитория и установленного архива.
[Нативный стенд](../../test/graph-canvas-browser.html) открывается после сборки
через `scripts/test-grid-canvas-browser.mjs --report <path>`.

- Совпадение команд рисования для прежнего вызова, `undefined` и `false`.
  Явное включение, однократное считывание опции, виды ошибок и их приоритет.
- Добавление и удаление вершин с инцидентными рёбрами при `p = 0, 0.25, 0.5, 1`,
  включая переход из пустого графа и в пустой граф.
- Перенаправление к новой вершине одновременно с удалением старой, движение
  общего конца, переход в петлю, разворот стрелки и перестановка концов
  ненаправленного ребра. Проверяются привязка концов, непрозрачность и подписи.
- Уплотнение и расширение параллельных групп, встречные рёбра и несколько петель.
  Проверяются плавный сдвиг сохранённой полосы, границы и подписи рядом с ветвями.
- Такой же кадр после Seek и Previous, Restart без следов старого результата,
  восстановление после resize. Проверки на реальном Canvas охватывают обе темы,
  DPR, очистку прозрачного фона и восстановление состояния контекста.
