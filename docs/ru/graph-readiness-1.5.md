# Готовность динамического графа к 1.5.0

[English](../graph-readiness-1.5.md) · [API графа](graph-api.md) · [Динамический trace](graph-dynamic-topology.md) · [Переходы Canvas](graph-dynamic-canvas.md) · [Стягивание ребра](examples.md#стягивание-ребра)

**Историческая ревизия от 21 ноября 2026 года.** API версии описан в
[заметках к 1.5.0](release-1.5.md). В ревизии сравнили рабочую сборку с
опубликованным архивом 1.4.0. Динамический граф был готов к подготовке
минорного релиза 1.5.0. Блокеров в API, реализации и примере не обнаружено.

| Область | Результат |
| --- | --- |
| `/graph` | `createDynamicGraphTrace` добавляет атомарный `edit`, стабильные ID вершин и рёбер и запрет повторного использования удалённых ID. При ошибке сохраняются снимок, индекс и история ID. Событие `edit` входит в отдельный `DynamicGraphEvent`. Контракты `GraphEvent`, снимков и проекции сцены сохраняются. |
| `/canvas/graph` | `topologyTransitions: true` плавно показывает появление и удаление, рисует старый и новый маршруты перенаправленного ребра с их концами и интерполирует полосы сохранённых рёбер. Пропуск опции, `undefined` и `false` сохраняют поведение 1.4.0. Размеры, DPR и контекст без clipping остаются в ведении приложения. |
| Стягивание ребра | Один `edit` удаляет `B` и `AB`, перенаправляет `BC` и `BD` с сохранением ID. `AC` и `BC` становятся параллельными. Зелёный результат выделяет `A`, `BC` и `BD`. Previous и Restart работают в обоих режимах Player, а полная история позволяет вернуться к промежуточному кадру. |
| Документация EN/RU | Оба README, индекс API, справочники графа и каталог примеров указывают, какие функции доступны в сборке из репозитория. В Canvas-справочнике уточнено действующее требование к контексту без clipping для полной очистки bitmap. У прежних отчётов сохранены даты и объём проверок. |

Карта экспорта по-прежнему содержит 16 путей. В рабочей сборке 34 экспорта
времени выполнения и 189 экспортов типов (177 различных имён). Прежним
импортам миграция не нужна. Для `/graph` по-прежнему достаточно ES2022
без DOM. Для `/canvas/graph` нужны ES2022 и DOM, а для отрисовки — контекст
HTML Canvas 2D. Новых зависимостей времени выполнения нет.

## Проверки

- Сборка сравнена с сохранённым npm-архивом 1.4.0, integrity которого
  совпала с [отчётом о публикации](../releases/1.4.0.json). Вне реализации
  графа и её деклараций сгенерированные файлы отличались только переводом
  строки в `dist/player/mount.js`.
- Прежние декларации графа совпали после исключения заявленных добавлений.
  Для фиксированного trace совпали шаги и проекции сцен на старте, отметках
  и подписях, смене раскладки и завершении. Все 150 сравнений команд Canvas
  совпали с 1.4.0 для обеих тем, пяти значений прогресса и трёх способов
  выбрать поведение по умолчанию.
- В репозитории прошли 788 тестов. Установленный архив прошёл 521 тест
  выполнения, проверку TypeScript 6.0.3 в режимах NodeNext и Bundler и
  проверку изоляции бандлов на Node 22.17.0. Архив собран с рабочей версией 1.4.0.
- Оба README и changelog совпали с файлами локального архива побайтно.
  Проверены 457 ссылок и якорей в репозитории. Блоки TypeScript в двух
  справочниках динамического API совпадают в EN и RU.
- Во встроенном Chromium прошли 24 нативные проверки Canvas графа. На
  странице стягивания повторно проверены Next, Previous и Restart с обоими
  типами источника. Пять постоянных тестов примера проверяют атомарный снимок,
  стабильные ID, полосы рёбер, зелёный результат, перемотку и Restart.

## Релизные шаги по итогам ревизии

1. Установить 1.5.0 в `package.json` и в двух корневых полях версии
   `package-lock.json`. Оформить changelog и заметки к релизу EN/RU.
   Привести оба README, текущие справочники API и окружений в соответствие
   с 1.5.0. Указать версию функций графа, прежние пути импорта и явное
   включение переходов Canvas.
2. Собрать и установить точный архив 1.5.0. До тега проверить его английский
   и русский README, changelog, версию, экспорты, ссылки и описания функций.
   Сверить их с документацией EN/RU в репозитории. Расхождения исправить
   в релизном коммите.
3. Закоммитить проверенные релизные изменения и отправить в origin.
   Дождаться всех 11 задач CI на точном SHA. Матрица включает шесть задач
   Node/ОС, четыре проверки потребителей TypeScript и проверку изоляции
   бандлов. Для нового релизного SHA требуется свой прогон CI.
4. После разрешения на публикацию создать `v1.5.0` и стабильный GitHub
   Release на этом SHA. Дождаться npm workflow, сверить точную версию,
   `latest`, подпись, provenance и README в реестре с архивом. Сохранить
   подтверждение публикации и актуализировать статус релиза EN/RU.
