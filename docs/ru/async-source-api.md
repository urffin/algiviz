# Асинхронный адаптер источника: публичный API

[English](../async-source-api.md) · [Поведенческий контракт](async-sources.md) · [План развития](../optional-player-proposal.md)

## Опубликовано в 0.15.0, 2026-11-13

В версии 0.15.0 опубликованы один runtime-экспорт `createAsyncSource` и пять
публичных типов из `@grundyjs/algiviz/playback`. См.
[проверку релиза](../releases/0.15.0.json). Новые entry point и зависимости не добавлены. Синхронные API и
/player сохранены для прежних источников; async-интеграция реализована отдельно.

Адаптер владеет одним ленивым сеансом источника и запрашивает неизменяемые
состояния. Он не рисует, не назначает индексы кадров, не запускает часы, не хранит
окно перемотки и не перезапускается сам. Эти возможности и один слот готового
результата принадлежат потребителю. Для Restart создаётся новый адаптер
по прежним правилам владения/очистки. Опция источника `/player`,
статусы и общий отчёт виджета описаны в отдельном [проекте интеграции](player-async-api.md).
Они реализованы в виджете и не являются дополнительными headless-экспортами.

## Публичные декларации

```ts
export interface AsyncSourceSignal {
    readonly aborted: boolean;
    readonly reason: unknown;
    subscribe(listener: (reason: unknown) => void): () => void;
}

export type AsyncSourceFactory<State> =
    (signal: AsyncSourceSignal) => AsyncIterable<State>;

export type AsyncSourceReadResult<State> =
    | { readonly kind: "value"; readonly value: State }
    | { readonly kind: "done" }
    | { readonly kind: "cancelled"; readonly reason: unknown };

export type AsyncSourceCloseResult = (
    | { readonly kind: "completed" }
    | { readonly kind: "disposed"; readonly reason: unknown }
    | { readonly kind: "failed"; readonly error: unknown }
) & {
    readonly cleanupErrors: readonly {
        readonly phase: "abort-listener" | "return";
        readonly error: unknown;
    }[];
    readonly lateReadError: { readonly error: unknown } | null;
};

export interface AsyncSource<State> {
    readonly signal: AsyncSourceSignal;
    readonly waiting: boolean;
    readonly closed: Promise<AsyncSourceCloseResult>;
    next(): Promise<AsyncSourceReadResult<State>>;
    dispose(reason?: unknown): void;
}

export declare function createAsyncSource<State>(
    factory: AsyncSourceFactory<State>,
): AsyncSource<State>;
```

Этот объект не является `AsyncIterable`, `AsyncIterator` или playback `Player`.
Результат явно различает отмену и конец итерации. Публичных `return()`, `throw()`,
`reset()` и отмены отдельного чтения нет: владелец закрывает весь сеанс.

## Создание и next()

`createAsyncSource(factory)` синхронно проверяет, что фабрика вызываема, иначе
бросает `TypeError`. Фабрика и получение итератора ещё не выполняются. `signal`
и `closed` сохраняют идентичность с момента создания; чтение их и `waiting`
не начинает работу. При первом `next()` фабрика получает именно этот сигнал
и возвращает `AsyncIterable<State>` непосредственно, без promise и без
синхронного iterable. Инициализация выполняется внутри итерации.

Ошибки фабрики, получения итератора, чтения и протокола отклоняют promise запроса
с исходным значением throw/reject. Созданные адаптером ошибки протокола имеют
тип `TypeError`; первый результат `done` даёт `RangeError` пустого источника.
Обнаруженный естественный EOF, включая пустой источник, не требует `return()`.
`undefined` допустим и как состояние, и как значение отклонения: проверять нужно
ветку результата/обёртку ошибки, а не truthiness её содержимого.

| Ситуация | Результат next() |
| --- | --- |
| Активный сеанс без запроса | При необходимости лениво получает итератор и запрашивает одно значение. Чтения вперёд нет. |
| Запрос ещё не завершён | Возвращает **тот же объект promise**. Не ставит шаг в очередь и не вызывает итератор повторно. |
| Пришло состояние | Разрешается веткой `value`. Адаптер не хранит историю или текущее состояние для повтора. |
| EOF после хотя бы одного значения | Разрешается веткой `done`, завершает сеанс естественно. Последующие вызовы дают `done` без I/O. |
| Ошибка операции | Отклоняется с основной ошибкой сразу, без ожидания очистки. Последующие вызовы отклоняются с тем же значением без I/O. |
| Сеанс закрыт владельцем | Разрешается веткой `cancelled` с первой причиной dispose, без I/O. |
| dispose обработан адаптером раньше результата ожидающего чтения | Общий публичный promise сразу получает `cancelled`; внутренний запрос итератора продолжает наблюдаться до завершения. |

`waiting` истинен, пока публичный запрос не урегулирован, включая получение
итератора; становится ложным до доставки результата/отклонения. Логический
dispose сразу сбрасывает его, даже если внутренний запрос/очистка ещё идут.
Поэтому `waiting: false` не означает завершённый `closed`. Callback статуса нет.

Урегулированный promise нельзя изменить. Если `value` получен до dispose,
но continuation потребителя выполняется позже, он всё ещё получит значение.
Виджет обязан проверить идентичность сеанса и актуальное намерение показа.
Pause/Previous не закрывают адаптер: используют существующий promise и сохраняют
готовый результат у потребителя. Нельзя автоматически вызывать `next()` при
каждом результате на паузе или в цикле promise: это явно запросит новые данные.

Адаптер наблюдает внутренние promise итерации/очистки. Потребитель всё равно
обязан ожидать или обрабатывать promise, полученные от `next()`. Отдельного
error-callback, автоматического повтора и таймаута нет.

## Сигнал отмены

`AsyncSourceSignal` — небольшой протокол без DOM, **не** платформенный
`AbortSignal`. Он не зависит от EventTarget, AbortController или типов Node.
Публичного контроллера нет: отменой владеет только адаптер.

- Изначально `aborted` ложен, `reason` равен undefined. `dispose(reason)` меняет
  оба поля до уведомлений. Пропущенная причина тоже undefined: проверять отмену
  нужно через `aborted`. Фатальная ошибка источника отменяет сигнал с исходной
  ошибкой как причиной. Естественный EOF сигнал не отменяет.
- Отмена необратима. Первое терминальное событие определяет исход: поздний
  dispose не меняет причину, ошибку, естественное завершение или отчёт.
  Pause сигнал не отменяет.
- `subscribe` регистрирует синхронный обработчик; возвращаемая отписка идемпотентна
  и не бросает исключений. Отдельные подписки — отдельные регистрации. При отмене
  оставшиеся обработчики вызываются в порядке регистрации не больше одного раза;
  удаление до своей очереди подавляет вызов. Ошибка обработчика записывается как
  `abort-listener` и не прерывает остальные уведомления/очистку.
- Подписка после отмены немедленно вызывает обработчик с сохранённой причиной
  и возвращает пустую отписку. Исключение этого прямого позднего вызова выходит
  из `subscribe`, не меняя существующий отчёт. Невызываемый listener даёт
  `TypeError`. Асинхронные обработчики не поддерживаются.
- Естественное закрытие освобождает подписки без уведомления; последующая подписка
  на естественно завершённый сигнал возвращает пустую отписку. Терминальный отчёт
  не остаётся изменяемым ради будущих ошибок явно вызванных пользователем подписок.

Приложение в браузере связывает сигналы явно. Этот пример требует типов DOM,
а декларациям адаптера выше достаточно ES2022:

```ts
const source = createAsyncSource(async function* (signal) {
    const controller = new AbortController();
    const unsubscribe = signal.subscribe(reason => controller.abort(reason));
    try {
        const response = await fetch("/states/first", { signal: controller.signal });
        if (!response.ok) throw new Error(`HTTP ${response.status}`);
        yield await response.json() as unknown;
    } finally {
        unsubscribe();
    }
});
```

Передавать `AsyncSourceSignal` прямо в опцию signal у `fetch` этот API не позволяет.
Среды без AbortController могут связать отмену с другим кооперативным механизмом.
Если фабрика бросает исключение до передачи итератора, за приобретённые
и не переданные ресурсы отвечает сама фабрика.

## dispose() и closed

`dispose(reason?)` синхронно аннулирует сеанс, отменяет публичный запрос
по правилам выше и начинает кооперативное закрытие. Он идемпотентен и не бросает
ошибок источника/обработчиков/return: они доступны в `closed`. Dispose до первого
чтения не вызывает фабрику. Уже урегулированный запрос изменить невозможно.

`closed` — один неизменный promise на адаптер. Он не отклоняется и сам не начинает
работу. Остаётся незавершённым до EOF, фатальной ошибки или dispose **и завершения
всех принадлежащих адаптеру операций получения итератора, чтения и return**.
Если потребитель перестал читать до EOF, он должен вызвать dispose для начала
закрытия. Источник может игнорировать отмену вечно; тогда `closed` тоже останется
незавершённым. Отмена публичного запроса и логический dispose его не ждут.

| Поле отчёта | Значение |
| --- | --- |
| `kind: "completed"` | Естественный EOF после хотя бы одного состояния. `cleanupErrors` пуст, `lateReadError` равен null. |
| `kind: "disposed", reason` | Первой была отмена владельцем; причина хранится по ссылке, включая undefined. Позднее отклонение источника не меняет исход на failed. |
| `kind: "failed", error` | Первой была ошибка активной фабрики/получения итератора/чтения/пустого источника. Это то же исходное значение, с которым отклонён `next()`, без обёртки очистки или повторного уведомления. |
| `cleanupErrors` | Ошибки обработчиков отмены и iterator return в порядке наблюдения. Throw getter/вызова return, reject return и некорректный/нетерминальный результат имеют phase `return`. Это настоящие ошибки очистки: при замене нельзя молча считать такое закрытие успешным. |
| `lateReadError` | Null либо одна обёртка позднего отклонения/ошибки протокола внутреннего запроса после отмены. Только диагностика: не делает отмену/Restart неуспешным, не подменяет исходную ошибку и не создаёт новое отклонение запроса. Обёртка сохраняет reject с undefined. Поздние значения отбрасываются без сохранения в отчёте. |

Если итератор не завершился естественно, его опциональный `return()` вызывается
один раз после завершения начатого `next()`. Методы итератора не пересекаются.
Результат return должен быть объектом с `done: true`, иначе в очистку записывается
`TypeError`. Значения, выдаваемые при закрытии, не вычитываются. Отсутствие return
само по себе не ошибка: тогда внешние ресурсы освобождает источник через сигнал.
Отчёт подтверждает завершение принадлежащих адаптеру вызовов, а не произвольных
ресурсов. Самостоятельная ошибка очистки оставляет `kind: "disposed"` с непустым
`cleanupErrors`, а не выдаёт себя за ошибку чтения активного источника.

Объект отчёта, обёртки диагностики и массив ошибок неизменяемы; состояния,
причины и значения ошибок не копируются и не замораживаются глубоко. История
сеансов не хранится: каждый отчёт относится к одному адаптеру. Будущий виджет
читает его без повторной доставки основной ошибки и без callbacks после
логического dispose. Для ожидания очистки проверяется `cleanupErrors`,
а не любое наличие диагностического `lateReadError`.

## Проверки типов на этапе проектирования

Историческая проверка до реализации, 2026-11-13: TypeScript 6.0.3 принял точный блок деклараций с позитивными
и негативными потребителями в памяти в NodeNext и Bundler, как с одним ES2022
без ambient-типов, так и отдельно с примером связи сигналов и DOM. Все четыре
проверки прошли. Блоки деклараций и примера EN/RU совпадают. Файлы не генерировались,
адаптер не реализован. Проверены предлагаемые типы, а не экспорты установленного
пакета или runtime-поведение.

Проверить вывод типов для async-генераторов/своих async iterable; исчерпывающее
сужение веток чтения/закрытия; undefined в состояниях/ошибках/причинах; readonly
поля и диагностику; отказ для sync/promise-фабрик, изменения сигнала и применения
как итератора. Скомпилировать декларации/потребителей только с ES2022 без ambient
типов в NodeNext и Bundler, а явную связь сигналов — отдельно с DOM.

Приёмочные runtime-сценарии требуют один promise для повторных запросов,
быструю отмену публичного чтения при долгой очистке, порядок терминальных событий,
разницу поздней ошибки и сбоя return, порядок/отписку/ошибки обработчиков,
естественный/пустой EOF и сценарии адаптера из поведенческого контракта. Это
покрыто проверками реализации ниже; сценарии виджета остаются отдельными.
Одна лишь проверка типов не подтверждает runtime-поведение.

## Реализация и локальные проверки

Адаптер реализован в [async-source.ts](../../src/playback/async-source.ts)
и экспортирован через `/playback`. Прошли все **244 теста**, включая **19 тестов
асинхронного источника**. [Проверки адаптера](../../test/async-source.test.mjs)
с управляемыми promise покрывают общее ожидание, быструю отмену публичного запроса
при долгой физической очистке, последовательные методы итератора, гонки исходов,
поздние ошибки отдельно от ошибок очистки, пустой/естественный EOF, порядок
обработчиков и повторный вход с dispose. Они также прошли
с `--unhandled-rejections=strict`.

Свежая установка локального npm-архива прошла точный перечень runtime-экспортов,
запрет приватных путей, строгих headless-потребителей с одним ES2022
и DOM/runtime-потребителей с TypeScript 6.0.3 в NodeNext и Bundler. Все 19 тестов
адаптера также прошли из установленного архива. DOM-потребитель проверяет явную
связь с AbortController. Проверка изоляции browser ESM bundles успешна. Это
локальные проверки пакета, не публикация или CI конкретного коммита. Управление виджетом, ожидание в RAF и нативные UI-проверки записаны отдельно
в [API интеграции](player-async-api.md).
