## Решение

Модуль близок к стабилизации как необязательный инструментарий для **числового
массива фиксированной длины с перестановками и одним удерживаемым элементом**.
Это не универсальная модель любых коллекций. Найденная проверка индексов swap/shift
исправлена в рабочей версии и закреплена регрессионными тестами (см. статус выше).
Масштабной переделки формата снимков, новых операций или переименований не требуется.

## Проверенный публичный контракт

| Часть | Оценка |
| --- | --- |
| createArrayTrace | Немедленная проверка конечных чисел; копия входа; start → операции → done; неизменяемые снимки |
| defineArrayAlgorithm | Алгоритм принадлежит приложению; iterate ленивый, steps собирает замороженную историю |
| Item | Неизменяемые id/value; одинаковые значения различаются по идентичности |
| ArraySnapshot | slots + held, маркеры областей и счётчики; длина slots фиксирована |
| compare/highlight | Ссылки на занятые позиции или held; compare считает одно сравнение, highlight не меняет счётчики |
| swap/select/shift/insert | Достаточны для обменов и сортировки вставками; обычные корректные вызовы сохраняют элементы |
| pass/done | События и метаданные; не исполняют сортировку и не доказывают упорядоченность |
| player/timeline | Тонкие адаптеры универсального playback; player распознаёт done, timeline использует длину истории |

## 1. Исправить до стабилизации: held принимается вместо числового индекса

`src/array/trace.ts`, методы swap и shift, используют общий item(position).
Этот helper намеренно принимает строку held для compare/highlight, но поэтому
пропускает её и в операции с числовыми позициями. Типы TypeScript корректны;
проверка JavaScript-вызовов неполна.

Воспроизведение на публичном API:

```js
const a = createArrayTrace([2, 1]);
a.start();
a.select(0);
const step = a.swap('held', 1); // Должен выбросить RangeError, сейчас принимается.
```

Получается slots = [null, item-0], held = item-0: item-1 потерян, item-0 повторён.
В отдельном свежем trace вызов shift('held', 0) заполняет пустую позицию
удерживаемым элементом, но не очищает held. Нарушается обещанная атомарность
ошибочных операций. Ранее выданные снимки остаются неизменяемыми, однако рабочее
состояние и следующие снимки уже некорректны.

Рекомендация: отдельно проверять числовые индексы всех параметров, которые
объявлены number, до lookup, regions, изменения slots, счётчиков и номера шага.
Не расширять swap/shift до поддержки held: для этого есть select/insert.

Необходимые проверки:

- swap('held', i), swap(i, 'held'), shift('held', hole) отклоняются при наличии held.
- После ошибки следующий корректный снимок имеет ожидаемый индекс и счётчики.
- slots + held содержат каждый исходный id ровно один раз; число пустых позиций
  равно наличию held; старые снимки не изменились.
- compare/highlight по-прежнему разрешают held.

Это блокирующая стабилизацию ошибка проверки аргументов, не причина менять
корректный пользовательский код или алгоритмы.

## 2. Уточнить перед 1.0: границы и семантика модели

Следующие решения уже следуют из реализации и должны быть явно закреплены:

- Item.id уникален в пределах одного trace, а не глобально. Для объединения
  нескольких массивов в одной сцене приложение задаёт собственное пространство id.
- held хранит максимум один элемент. shift перемещает существующий элемент в
  пустую позицию; insert возвращает held. Удаление/добавление значений и изменение
  длины не являются операциями этой модели.
- writes считает shift/insert как одну запись, swap как две; select не учитывается.
  Это метрика операций trace, а не буквальное число присваиваний JavaScript.
- sortedPrefixLength/sortedSuffixLength — утверждения автора алгоритма. Пропуск
  сохраняет значение; уменьшение и перекрытие сейчас разрешены. Не вводить
  автоматическую проверку сортировки или монотонности без изменения контракта.
- done не выставляет маркеры автоматически; reverse с done — допустимый алгоритм.
- pass.end — индекс позиции (в пределах массива), а не длина или количество
  проходов. Для пустого массива pass не нужен: start и done допустимы.
- Вход iterate читается/копируется на первом next, а не при вызове iterate.
  start/done нужно yield явно: defineArrayAlgorithm не вставляет их автоматически.
- Каждый emit копирует slots: время/аллокации снимка O(n), даже для compare.
  Генератор не накапливает историю, но не делает снимки бесплатными.
- Категории ошибок и атомарность можно обещать; текст сообщений не стоит
  объявлять стабильным API.

Закрытый ArrayEvent удобен для стандартного renderer. Свои события и структуры
уже поддерживаются через /playback + /scene: расширяемый event registry здесь
не требуется. Сам факт добавления нового ArrayEvent в будущем надо оценивать
с учётом пользовательских exhaustive-switch проверок.

## 3. Неблокирующее улучшение типов: SortedRegions и undefined

В runtime start({ sortedPrefixLength: undefined }) сохраняет текущий маркер.
При exactOptionalPropertyTypes текущий SortedRegions этот объект отвергает:
опциональное поле объявлено как number, без union undefined. То же касается suffix.

Рекомендация: разрешить explicit undefined именно во входном SortedRegions,
согласовав его с остальными конфигурациями плеера и палитры. Это совместимое
расширение типов, его следует проверить на установленном пакете. Не обязательно
менять выходной ArraySnapshot или добавлять новые экспортируемые типы.

## Что сохранить

- Четыре runtime экспорта и текущие имена; алгоритмы снаружи библиотеки.
- Детерминированные идентичности, независимые неизменяемые снимки и ленивый iterate.
- Раздельные headless операции /array и Canvas backend /canvas.
- Явное завершение done для createArrayPlayer; не смешивать его с исчерпанием
  createStatePlayer под одним неявным overload.
- Числовой Item: generic value/comparator, произвольные отсортированные диапазоны,
  несколько held-элементов и динамическая длина требуют отдельных сценариев,
  а не добавления возможностей ради предполагаемой универсальности.

## Основания проверки

Прочитаны все исходники src/array, публичные декларации и операции в insertion,
bubble и пользовательском reverse; проверено использование событий Canvas renderer.
Запущены 31 тест из public-api, insertion-sort, bubble-sort и completion-matrix.
Все прошли, включая 2186 эталонных трасс и атомарность уже покрытых ошибочных операций.
Пробами воспроизведены оба дефекта held, текущие счётчики, разрешённое перекрытие
маркеров, lazy copy и finally при раннем return. Для SortedRegions сопоставлены
runtime и диагностика TypeScript с exactOptionalPropertyTypes.
