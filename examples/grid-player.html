Grid · BFS shortest path

Find a shortest path from S to T between blocked cells. Move north, east, south or west; every move costs one. BFS discovers each cell once, using a first-in, first-out queue.

Detailed maze: seeded generation, BFS/DFS, custom walls and drawing

S: start. T: target. #: blocked. Purple: queued. Yellow: current. Grey: processed. Captions d=N show shortest distances from S. Green cells and the connecting line show the final path.

Coordinates below are (row,column), counted from 1. The default 5 × 7 grid has a shortest path of 10 moves. Try the divided grid for an unreachable target, or S=T for a zero-move path: one green cell, without a line.

Search stops when T is dequeued, so other cells may remain in the queue. Neighbors are checked in north–east–south–west order; another order can choose a different shortest path of the same length. No diagonal moves, weights or automatic maze generation are involved.

Use Previous and Next to replay the result. Full history also supports seeking. Restart repeats the selected grid with a fresh queue and trace. Changing the grid or mode starts again.

The BFS, obstacles, queue and parents belong to this example. The library supplies /grid steps, /canvas/grid drawing and Player controls. Shared timing is 650 ms per step with a 1,000 ms final hold. The algorithm uses O(N) work and memory; copying O(N) snapshot data per step makes full history O(N²). The generator retains a fixed window of 32 positions.

This repository page uses the local build. /grid and /canvas/grid require @grundyjs/algiviz 1.3.0 or newer.
