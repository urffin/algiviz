Graph · depth-first search

Follow one branch, then return to the caller and resume its next neighbor. The explicit call frames reproduce recursive DFS. A DFS tree path is not necessarily shortest. Try the isolated H, the start itself or no target.

Outline: unseen. Purple: active calls. Yellow and a ring: current call. A check mark: finished. Purple edges: DFS tree. Green: restored path. Stack bottom is at the bottom; each frame records the next neighbor cursor.

Apply loads the selected graph, start and target. Restart and mode changes use the applied inputs. Mark a vertex before entering its call, so cycles never create repeated calls. The parent frame advances its neighbor cursor before entering a child. Return resumes the suspended frame.

With the default neighbor order, discovery is A, B, D, G, E, C, F; returns are F, C, E, G, D, B, A. The path to F has 6 edges: A → B → D → G → E → C → F. BFS on the same graph finds A → C → F (2 edges). H is unreachable. Depth is DFS tree depth, not shortest distance. Traversal finishes before path reconstruction.

The algorithm, graph, vertex/edge/call objects and renderer belong to this example. Only simple undirected graphs are accepted (self-loops and parallel edges are rejected). Neighbor order follows edge input order. Traversal takes O(V + E) time and O(V) auxiliary space; full immutable history takes up to O(V(V + E)) space. Generator mode retains adjacent snapshots, with snapshot creation still costing time. No package export is added.
