Graph · breadth-first search

Explore an undirected graph layer by layer with a first-in, first-out queue. Complete the reachable component, then restore one shortest path by following parents. Try the isolated H as a target, or choose the start itself for a zero-edge path.

Outline: undiscovered. Purple: queued. Yellow and a ring: current. A check mark: processed. Purple edges: discovery tree. Green: restored path. S / T marks a vertex that is both start and target. A dot follows the examined edge. The graph stays fixed; the queue moves briefly when entries change.

Apply loads the selected graph, start and target. Restart and mode changes replay the applied inputs. Vertices are marked on enqueue, so cycles and repeated edges do not enqueue them twice. An undirected edge is inspected from both ends; a self-loop has one adjacency entry. Neighbor order can change the chosen shortest path, but not its length. Dash means not discovered yet; after traversal ∞ means unreachable. Restoring the path does not change traversal counters.

The default example has 8 vertices, 9 edges and an isolated H. From A, the queue reaches a maximum size of 3; the traversal processes 7 vertices and inspects 18 neighbor entries. To G, it restores A → B → D → G.

The algorithm, graph state and vertex/connection/queueEntry visualizations belong to this example. AlgiViz supplies playback, cached projection and scene dispatch. The generator retains adjacent snapshots; full history keeps every snapshot. Building snapshots still costs work and memory in either mode. No graph API or built-in BFS algorithm is added to the package.
