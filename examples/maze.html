Maze generation and pathfinding

Carve a maze with randomized DFS, then run a BFS wave or DFS with backtracking on the same walls. The generated maze is a tree: both searches find its unique route. Choose the cycle preset to see a longer DFS route.

S: start, T: exit, ring: current cell. Purple: waiting queue or suspended calls; yellow: current; gray: finished; green: restored route. BFS numbers are shortest distances; DFS levels are tree depths. Dense grids hide labels. Coordinates start at 1; numeric ids in code start at 0.

Apply captures the input. Restart and mode changes replay the applied input, not draft form values. Generation always starts at the top-left cell and finishes the whole maze. Search stops when T becomes current. Changing search endpoints does not change the walls. Presets have no invented generation history.

For 7 × 5, seed 2, generation visits 35 cells, opens 34 passages and checks 140 directions. BFS and DFS both find 12 transitions from (1,1) to (7,5). In the cycle preset BFS uses 1 transition and DFS uses 5. The disconnected exit is unreachable; selecting the start as exit produces a zero-transition path.

The algorithm, wall model and aggregate maze-grid scene object belong to this example. The public /playback and /scene APIs handle frames and rendering dispatch. The algorithm uses O(N) working memory. Immutable snapshots copy O(N) data per event; full history takes O(N²) memory, while generator mode retains adjacent snapshots in O(N) memory but still pays their copying cost. The website's packed/checkpointed history is a different implementation.
