Quick sort partitions

Compare Lomuto with three-way partitioning on the same array. Both save the last value in the active range as pivot. Equal values carry labels so their order can be tracked.

Up to 64 finite values with history or 2,000 in generator mode. History stores full snapshots; generator playback does not. Dense charts hide labels and the text status previews 24 cells.

Lomuto uses a strict < comparison and places one pivot into its final position. Three-way partitioning keeps smaller, equal, unchecked and greater regions. After an exchange with the greater region, the incoming item must be checked again. Only the smaller and greater regions recurse.

For n ≥ 2 equal values: three-way uses 2n checks, zero swaps and one partition; Lomuto uses n(n − 1)/2 checks. Counts refer to actual < and > operations. Swaps with the same position are omitted.

Both variants are unstable in general. Balanced partitions take Θ(n log n); worst-case time is Θ(n²). Direct recursion uses up to O(n) stack space; copying the input costs O(n). History can require O(n³) memory separately. Green means a final position. Bars show magnitude, while labels preserve the sign.
