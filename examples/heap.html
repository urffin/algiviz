Heap sort: tree and array

An application-owned algorithm and synchronized tree/array scene using the public scene and playback APIs. A max-heap is built bottom-up; each maximum moves to its final array position before the remaining heap is restored.

History: up to 64 values. Generator: up to 2,000. Finite numbers only. Letters distinguish equal values; dense charts hide labels and text status previews the first 24 cells.

Yellow marks active comparisons, cyan the chosen child, and an outline the parent. Green cells are final; the vertical line marks the sorted suffix. The tree uses fixed positions while the same element identities move in both views. Up to 15 cells wrap on narrow screens; larger arrays use a dense row with unreadable labels hidden. Full numeric values are available in the input; the status previews 24 items.

Bottom-up construction takes O(n), sorting O(n log n) in the worst case. Equal input takes linear work with early stopping. Iterative in-place sorting needs O(1) auxiliary space; this example copies the input and generator snapshots cost O(n). Full history can cost O(n² log n). Heap sort is not stable: try 2, 2, 1 to see 2a and 2b reverse order. This is application-owned example code, not a new package export.
