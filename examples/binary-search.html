Binary search: first occurrence

Inspect the middle of a sorted array and discard half of the remaining interval. When a value matches, keep it as a candidate and continue left to find the first occurrence.

History: up to 64 values. Generator: up to 2,000. Unsorted input is rejected. Values and indices wrap for up to 32 items; dense arrays hide labels. The status previews 24 values; full values remain in the input.

Purple: remaining closed interval [low, high]. Yellow: inspected middle. Cyan: saved candidate. Green: confirmed first occurrence. Gray: excluded indices. Indices start at zero. Highlights change discretely. Long values are abbreviated on canvas.

If values[mid] < target, move low to mid + 1. Otherwise move high to mid − 1; save mid first if equal. The answer is a zero-based index or −1. The counter counts inspected middle elements, not individual comparison operators.

The iterative search uses O(log n) worst-case time and O(1) extra algorithm memory. This demo validates and copies input once in O(n), shares the frozen array between snapshots and stores O(n + log n) history data. Generator playback keeps O(n) input data and adjacent snapshots. No sorting is performed and input is never rearranged.

This is application-owned example code using public /playback and /scene APIs, not a built-in algorithm or a new package export.
